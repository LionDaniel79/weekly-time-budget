# 월간 통계 멈춤 브라우저 재현 결과

- 재현 기준 커밋: `906079bdda53317937d242b0ca0f96686ef00293`
- 진단 CI: `460` (`30724831492`)
- 사용자 동작: 장기간 미사용 PWA에서 새 버전 적용 후 통계 → 월간 통계

## 실행한 진단

1. `현재 월간 통계 클릭은 2초 안에 완료되고 반복 전환 후에도 응답한다`
2. `구형 runtime 캐시가 최신 통계 셸 파일보다 먼저 반환되지 않는다`

## 관찰 결과

- 깨끗한 브라우저와 동일 세대 자산에서는 월간 통계 클릭이 2초 안에 완료됐다.
- 주간 통계와 월간 통계를 20회 반복 전환해도 화면이 응답했고 콘솔 오류가 없었다.
- `weekly-time-budget-runtime-v1`에 `/src/statistics-offline-rescue.js`의 구형 본문 `/* stale-statistics-v13 */`을 넣은 뒤 현재 서비스 워커를 설치했다.
- 설치가 완료된 뒤 같은 경로를 `fetch()`했을 때 최신 셸 파일이 아니라 `/* stale-statistics-v13 */`이 반환됐다.

## 최초 실패 단계

`월간 집계`나 `통계 DOM 렌더링`이 아니라, 서비스 워커가 애플리케이션 JavaScript를 선택하는 **PWA 자산 조회 단계**에서 실패했다.

## 확정 원인

현재 서비스 워커의 `cacheFirst()`는 `caches.match(request)`로 모든 캐시를 통합 검색한다. 또한 같은 출처의 앱 JavaScript도 영구 유지되는 `weekly-time-budget-runtime-v1`에 저장할 수 있다. 그 결과 셸 캐시를 v13, v14, v15로 올려도 runtime-v1에 남은 과거 통계 파일이 최신 셸 파일보다 먼저 반환된다.

따라서 장기간 앱을 열지 않은 기기에서는 새 HTML과 서비스 워커가 활성화되어도 구형 통계 JavaScript가 함께 실행될 수 있다. 현식 님 기기와 다른 사용자의 기기에서 동작이 달랐던 현상, 여러 수정이 배포된 뒤에도 월간 통계 멈춤이 계속된 현상을 이 캐시 세대 혼합이 설명한다.

## 배제하거나 범위를 낮춘 가설

- 깨끗한 브라우저에서 현재 월간 집계와 렌더링은 정상 완료되므로, 월간 집계 함수 자체의 무조건적인 무한 반복은 재현되지 않았다.
- 주간↔월간 20회 반복도 통과했으므로, 현재 동일 세대 자산만 사용한 상태에서 탭 클릭 자체가 항상 멈추는 문제도 재현되지 않았다.
- 다만 통계 소유권이 여러 파일에 나뉘고 사용하지 않는 과거 코드가 남아 있는 구조적 위험은 별도로 제거한다.

## 수정 방향

1. 같은 출처 앱 셸 자산은 현재 셸 캐시에서만 조회한다.
2. Firebase CDN 모듈만 별도 런타임 캐시에서 조회한다.
3. 활성화 시 기존 `runtime-v1`과 구형 셸 캐시를 삭제한다.
4. 통계 기능의 상태·기간 선택·DOM 소유권을 하나로 통합하고 과거 코드를 제거한다.
5. 구형 runtime 캐시를 심은 실제 브라우저 테스트를 최종 회귀 테스트로 유지한다.
