# 통계 서브시스템 재구성 설계

- 작성일: 2026-08-01
- 대상 저장소: `LionDaniel79/weekly-time-budget`
- 작업 브랜치: `design/statistics-subsystem-rebuild`
- 상태: 구현 전 설계

## 1. 배경

운영 웹앱에서 주간·연간·월간 비교·연도별 비교는 동작하지만 `월간 통계` 탭을 누르면 화면이 멈추는 문제가 반복되고 있다. 지금까지 다음과 같은 부분 수정이 적용되었다.

1. 0분 통계의 DOM 후처리 반복 차단
2. 중복 통계 렌더러 제거
3. 기록 기간 모듈의 월 선택 DOM 소유권 차단
4. 서비스 워커 버전 갱신

그러나 실제 기기에서 증상이 계속되므로, 더 이상 개별 조건문을 추가하는 방식으로 수정하지 않는다. 통계 전체 흐름을 실제 브라우저에서 재현하고, 통계 상태·컨트롤·렌더링의 소유권을 하나로 통합한다.

## 2. 현재 구조 분석

### 2.1 현재 실행 흐름

통계 메뉴를 누르면 대략 다음 흐름이 실행된다.

```text
통계 메뉴 클릭
→ 통계 전용 클릭 가로채기
→ IndexedDB 캐시 조회
→ 캐시 통계 렌더링
→ Firestore 기록·대분류·보관 대분류·주간 예산 조회
→ 서버 통계 전체 렌더링
→ UI 상태 저장
→ document.body를 감시하는 여러 MutationObserver가 반응
→ 기록 기간·대시보드·타이머·선택 복원 모듈이 각자 DOM을 검사
```

현재 주 렌더러는 `statistics-offline-rescue.js` 하나지만, 통계의 실제 책임은 여러 파일에 나뉘어 있다.

| 책임 | 현재 담당 |
|---|---|
| 통계 데이터 캐시·서버 조회 | `statistics-offline-rescue.js` |
| 통계 탭·연도·월 상태 | `statistics-offline-rescue.js`, `ui-session-state.js` |
| 주간 기록 기간 이동 | `recorded-period-navigation.js` |
| 월 선택 가능 기간 계산 | `recorded-period-domain.js`, 실행이 차단된 `recorded-period-navigation.js` 코드 |
| 0분 목표 준수 표시 보정 | `recorded-period-navigation.js`의 DOM 후처리 |
| 통계 스타일 | `statistics-primary.css`, 런타임 스타일 삽입, `statistics-mobile-overflow.js` |
| 과거 통계 구현 | 실행하지 않는 `statistics-ui.js`, `statistics-session-state.js` |
| PWA 자산 제공 | `service-worker.js` |

### 2.2 월간 통계만 다른 점

월간 통계는 다른 모드와 달리 다음 흐름을 모두 가진다.

- 연도와 월 `<select>` 동시 생성
- 기록이 존재하는 연도·월의 활성 여부 판단
- 저장된 연도·월 상태 보정
- 월간 집계 실행
- 통계 화면 전체 `innerHTML` 교체
- 상태 저장과 전역 DOM 감시자 반응

월간 집계 함수는 연간 통계와 월간 비교에서도 재사용되므로, 집계 함수만을 유일한 원인으로 단정할 수 없다. 월간 전용 컨트롤·상태·렌더링의 결합 경로를 실제 브라우저에서 재현해야 한다.

### 2.3 검증상의 결함

현재 테스트는 Node의 `node --test` 중심이다. 기존 월간 멈춤 회귀 테스트도 실제 버튼을 누르는 대신 소스에 특정 문자열이나 조건문이 존재하는지 검사한다.

따라서 기존 CI 성공은 다음을 보장하지 못한다.

- 실제 브라우저에서 월간 버튼 클릭이 완료되는지
- 이벤트가 반복 호출되지 않는지
- 메인 스레드가 장시간 점유되지 않는지
- 여러 MutationObserver 사이에 순환이 없는지
- 구형 PWA에서 새 자산만 일관되게 로드되는지

### 2.4 PWA 캐시 세대 혼합 위험

현재 서비스 워커의 일반 `cacheFirst()`는 `caches.match(request)`로 모든 캐시를 통합 검색한다. 또한 같은 출처 자산도 동일한 함수가 처리하며, 영구 유지되는 `weekly-time-budget-runtime-v1`에 저장될 수 있다.

이 구조에서는 셸 캐시 버전을 올려도 런타임 캐시에 남은 같은 출처의 과거 자산이 새 셸 자산보다 먼저 반환될 가능성을 배제할 수 없다. 실제 브라우저에서 구형·신형 통계 파일이 섞이는 문제를 막으려면 캐시 종류별 조회 범위를 분리해야 한다.

이 항목은 월간 멈춤의 확정 원인으로 단정하지 않지만, 반복 배포 후에도 증상이 유지되는 상황을 설명할 수 있는 중대한 구조적 위험으로 취급한다.

## 3. 목표

1. 실제 브라우저에서 월간 통계 멈춤을 재현하고 원인 단계를 확인한다.
2. 통계 화면의 데이터·상태·기간 이동·렌더링·오류 처리를 하나의 기능 경계로 통합한다.
3. 통계 DOM을 통계 기능 외 모듈이 수정하지 못하게 한다.
4. 월간 버튼 클릭은 서버 재조회 없이 상태 변경·집계·렌더 한 번으로 끝나게 한다.
5. 기록이 없는 과거 월과 미래 월을 처음 렌더할 때부터 비활성화한다.
6. 사용하지 않는 과거 통계 코드와 런타임 CSS 삽입 코드를 제거한다.
7. 구형 PWA에서 업그레이드해도 같은 빌드 세대의 HTML·JS·CSS만 함께 사용하게 한다.
8. 실제 브라우저 회귀 테스트를 CI에 포함한다.

## 4. 비목표

이번 작업에서는 다음을 변경하지 않는다.

- 대시보드의 일간·주간 계산 방식
- 타이머·수동 입력·기록 저장 방식
- 성장·절제 목표의 달성률 계산 공식
- Firestore 데이터 구조
- 대분류 생성일·보관·복원 규칙
- 통계 화면의 항목 명칭과 핵심 정보 구성

통계 순수 계산에서 별도 오류가 발견되면 기존 의미를 유지하는 범위에서만 수정한다.

## 5. 권장 구조

### 5.1 통계 기능의 단일 소유자

새 `statistics-feature.js`가 다음을 전담한다.

- 통계 화면 진입·종료
- 캐시 우선 데이터 로드와 서버 갱신
- 통계 상태
- 주간·월간·연간·비교 탭 전환
- 주간 기록 기간 이동
- 연도·월 선택 가능 여부
- 집계 호출
- HTML 생성과 DOM 반영
- UI 상태 저장·복원
- 로딩·경고·오류·재시도 표시

`#statistics-view` 내부의 DOM을 수정하는 제품 코드는 이 모듈 하나만 허용한다.

### 5.2 데이터 로더 분리

`statistics-data-source.js`는 화면을 알지 못하는 데이터 계층으로 둔다.

입력:

- 사용자 ID
- 오프라인 런타임
- Firestore 어댑터
- 제한시간

출력:

```js
{
  entries,
  activeCategories,
  archivedCategories,
  weeklyBudgets,
  source: 'cache' | 'server',
  dataVersion
}
```

규칙:

- 캐시가 있으면 즉시 반환한다.
- 서버 갱신은 제한시간을 둔다.
- 탭 전환이나 연도·월 변경으로 서버를 다시 조회하지 않는다.
- 사용자 변경 시 이전 요청 결과를 폐기한다.
- 서버 성공 후 사용자별 스냅숏을 갱신한다.

### 5.3 통계 상태

통계 상태는 한 객체로 관리한다.

```js
{
  mode: 'weekly' | 'monthly' | 'yearly' | 'monthly-comparison' | 'yearly-comparison',
  weekStart,
  year,
  month,
  data,
  dataVersion,
  loadStatus: 'idle' | 'loading' | 'ready' | 'error',
  source: 'none' | 'cache' | 'server',
  warning,
  renderError
}
```

상태 변경은 `setStatisticsState()` 한 경로로만 수행한다. 같은 값으로의 변경은 렌더와 저장을 생략한다.

### 5.4 앱 화면 전환 연결

기본 앱의 `switchView()`는 화면을 바꾼 뒤 다음 이벤트를 한 번 발생시킨다.

```text
weekly-time-budget:view-changed
```

통계 기능은 이 이벤트에서 화면 진입을 감지한다. 통계 기능이 메뉴 클릭을 `preventDefault()` 또는 `stopImmediatePropagation()`으로 가로채지 않는다.

저장 상태 복원도 버튼을 인위적으로 다시 클릭하지 않는다. 복원된 상태를 통계 상태에 직접 적용한다.

## 6. 월간 통계의 확정 흐름

월간 탭 클릭은 다음 순서로만 처리한다.

```text
월간 탭 클릭
→ mode가 이미 monthly이면 종료
→ 현재 year/month를 기록 기간 인덱스로 보정
→ state를 한 번 변경
→ 월간 요약을 한 번 계산
→ HTML을 한 번 생성
→ #statistics-view를 한 번 갱신
→ UI 상태를 한 번 저장
```

동일한 `dataVersion`을 사용하는 동안에는 한 번의 월간 탭 클릭으로 렌더가 한 번만 발생해야 한다. 캐시 자료를 표시한 뒤 서버에서 실제로 새로운 `dataVersion`이 도착한 경우에만 한 번의 추가 렌더를 허용한다.

금지 사항:

- 월간 탭 클릭 시 Firestore 전체 재조회
- 렌더 후 다른 모듈이 연도·월 옵션 재생성
- 상태 복원을 위한 인공 클릭
- MutationObserver를 이용한 통계 DOM 후처리
- 이미 같은 상태인데 중복 렌더
- 렌더 뒤 목표 준수 문구를 다시 수정

## 7. 기록 기간 규칙

`recorded-period-domain.js`의 순수 함수를 재사용하되, 통계 기능이 결과를 직접 렌더한다.

### 7.1 월 활성 규칙

- 기록이 있는 과거 월: 활성
- 이번 달: 기록이 없어도 활성
- 기록이 없는 과거 월: 비활성
- 미래 월: 비활성

### 7.2 저장 상태 보정

저장된 연도·월이 더 이상 유효하지 않으면 다음 순서로 보정한다.

1. 같은 연도의 가장 가까운 이전 기록 월
2. 같은 연도의 가장 가까운 이후 기록 월
3. 이번 달

선택 가능한 월이 없는 과거 연도는 연도 목록에는 기록이 있는 경우만 표시한다.

### 7.3 주간 이동

- 이전 주는 가장 가까운 기록 주로 이동
- 다음 주는 가장 가까운 기록 주 또는 이번 주로 이동
- 이동 대상이 없으면 버튼을 비활성화

이 로직은 통계 기능 안에서 처리한다. `recorded-period-navigation.js`는 대시보드 기간 이동만 담당하도록 축소한다.

## 8. 렌더링과 오류 경계

### 8.1 렌더 원칙

- 통계 렌더는 동기식 순수 HTML 생성과 단일 DOM 반영으로 나눈다.
- 이벤트는 `#statistics-view`의 단일 event delegation으로 연결한다.
- `document.body` 전역 MutationObserver를 사용하지 않는다.
- 계산 결과는 `dataVersion + mode + period` 키로 메모이제이션한다.
- 데이터가 바뀌면 요약 캐시를 모두 무효화한다.

### 8.2 오류 처리

다음 단계를 각각 오류 경계로 감싼다.

1. 데이터 정규화
2. 기록 기간 인덱스 생성
3. 통계 집계
4. HTML 생성
5. DOM 반영

오류가 발생하면 브라우저를 멈추게 하지 않고 다음 화면을 표시한다.

```text
월간 통계를 표시하지 못했습니다.
문제가 발생한 단계: 월간 집계 또는 화면 생성
[다시 시도]
```

개발·테스트 환경에서는 오류 단계, 실행 횟수, 소요 시간을 기록한다. 운영 화면에는 내부 오류 상세를 노출하지 않는다.

## 9. 브라우저 재현과 회귀 테스트

### 9.1 Playwright 도입

실제 브라우저 통합 테스트를 CI에 추가한다. 외부 Google 로그인이나 실제 Firestore에 의존하지 않도록 통계 데이터 소스를 주입 가능한 구조로 만든다.

브라우저 테스트 fixture는 운영 통계 화면과 같은 `statistics-feature.js`를 사용하며, 데이터 소스만 결정론적 가짜 구현으로 교체한다.

### 9.2 필수 시나리오

1. 기록이 전혀 없는 사용자
2. 현재 월 기록만 있는 사용자
3. 여러 해·여러 달 기록이 있는 사용자
4. 활성·보관·삭제 대분류가 섞인 사용자
5. `createdDate`가 없는 기존 대분류와 생성일이 있는 새 대분류
6. 성장·절제 목표가 섞인 사용자
7. 요일 비율과 과거 주간 예산이 섞인 사용자
8. 캐시 자료를 먼저 표시한 뒤 서버 자료로 갱신되는 사용자
9. 서버 제한시간·실패 후 캐시 통계를 유지하는 사용자

각 시나리오에서 다음을 검사한다.

- 통계 메뉴 → 월간 통계 클릭 후 월간 제목과 컨트롤이 2초 안에 표시
- 주간 ↔ 월간을 20회 반복해도 화면이 반응
- 동일 `dataVersion`에서는 월간 클릭당 렌더 한 번
- 서버의 새 `dataVersion` 도착 시에만 추가 렌더 한 번 허용
- 처리되지 않은 예외와 콘솔 오류가 없음
- 기록 없는 과거 월과 미래 월이 비활성화
- 저장 상태 복원 후 인공 클릭이나 재조회가 발생하지 않음

### 9.3 성능 기준

테스트용 대용량 자료에서도 월간 탭 전환은 서버 조회 없이 완료되어야 한다.

기준 자료:

- 기록 5,000건
- 대분류 100개
- 주간 예산 260주

위 자료에서 순수 월간 상태 보정·집계·HTML 생성은 CI 환경에서 1초 이내에 완료되어야 한다. Playwright에서는 월간 버튼 클릭 후 월간 화면이 2초 이내에 상호작용 가능한 상태가 되어야 한다. 렌더 횟수 계약은 절대 시간과 무관하게 항상 적용한다.

### 10.1 삭제

## 11. 서비스 워커 재구성

### 11.1 캐시 역할 분리

- 셸 자산: 새 셸 캐시에서만 조회
- Firebase 원격 모듈: 런타임 캐시에서만 조회
- Firestore·Auth API: 캐시하지 않음
- 같은 출처의 앱 JS·CSS·HTML을 런타임 캐시에 넣지 않음

`caches.match(request)` 전역 검색 대신 명시적인 캐시 인스턴스의 `match()`를 사용한다.

### 11.2 업그레이드

- 새 셸 캐시 버전 사용
- 과거 셸 캐시 삭제
- 기존 런타임 캐시의 같은 출처 앱 자산 제거 또는 런타임 캐시 세대 교체
- 서비스 워커 제어권 변경 후 한 번만 새로고침하는 현재 안전장치 유지
- 운영 진단 시 확인할 수 있는 빌드 버전 표식 제공

### 11.3 업그레이드 테스트

- v13 → 새 버전
- v14 → 새 버전
- v15 → 새 버전

각 업그레이드에서 HTML·통계 JS·통계 CSS가 모두 같은 빌드 세대인지 확인한다.

## 12. 구현 순서

1. 현재 `main`에서 실제 월간 클릭 브라우저 테스트를 작성해 실패 또는 시간 초과를 확인한다.
2. 임시 계측으로 클릭·집계·렌더·상태 저장·복원·DOM 감시 실행 횟수를 확인한다.
3. 통계 데이터 소스를 DOM에서 분리한다.
4. 통계 단일 상태와 단일 렌더러를 구현한다.
5. 월간 기록 기간 선택을 통계 기능 안으로 이전한다.
6. `recorded-period-navigation.js`에서 통계 책임을 제거한다.
7. 과거 통계 파일과 런타임 CSS 삽입 코드를 삭제한다.
8. 서비스 워커 캐시 역할을 분리하고 업그레이드 테스트를 추가한다.
9. 모든 브라우저·순수 함수·기존 회귀 테스트를 실행한다.
10. Pages 산출물에 새 파일만 포함되고 삭제 파일이 없는지 검사한다.
11. 운영 배포 후 실제 주소에서 빌드 세대와 월간 클릭을 확인한다.

원인을 확인하기 위한 계측과 실패 재현이 끝나기 전에는 제품 동작 코드를 추측으로 수정하지 않는다.

## 13. 완료 기준

다음 조건을 모두 만족해야 완료로 판단한다.

- 현재 증상을 실제 브라우저 테스트로 재현하거나, 기존 구조의 중복 실행 또는 캐시 세대 혼합을 결정론적으로 실패시킴
- 월간 통계 클릭 후 2초 안에 상호작용 가능한 월간 화면 표시
- 빈 계정과 기록 많은 계정 모두 성공
- 주간 ↔ 월간 20회 반복 성공
- 동일 `dataVersion`에서 클릭당 월간 렌더 한 번
- 탭 전환 시 Firestore 재조회 없음
- 콘솔 오류와 처리되지 않은 Promise 오류 없음
- 기록 없는 과거 월과 미래 월 비활성화
- 대용량 기준 자료의 월간 상태 보정·집계·HTML 생성 1초 이내
- 주간·연간·월간 비교·연도별 비교 회귀 없음
- 목표 준수·예산·실제 기록 계산이 기존 순수 함수 결과와 일치
- 통계 화면을 수정하는 MutationObserver 없음
- 과거 통계 파일이 저장소·HTML·서비스 워커·Pages 산출물에서 제거됨
- PWA v13·v14·v15 업그레이드 테스트 성공
- 전체 Node 테스트·브라우저 테스트·Pages 검증 성공
- 운영 주소에서 새 빌드 세대와 월간 통계 정상 동작 확인
