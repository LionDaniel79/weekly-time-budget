# 카운트다운·카운트업 타이머 설계

## 1. 목표

시간 기록의 타이머 화면에 두 가지 방식을 제공한다.

```text
[ 카운트 다운 ] [ 카운트 업 ]
```

데이터 방식 값과 화면 순서는 다음과 같다.

```text
mode: countdown | countup
```

- **카운트 다운**: 시작 날짜의 해당 대분류 일간 예산에서 그날 저장된 기록시간과 현재 실행시간을 차감하여 표시한다.
- **카운트 업**: 기존 타이머 동작을 유지한다.
- 한 사용자에게 동시에 존재할 수 있는 활성 타이머는 하나다.

## 2. 기본 방식과 기존 데이터 호환

- 활성 타이머가 없을 때 기본 선택은 `countdown`이다.
- 탭 순서는 항상 `카운트 다운`, `카운트 업`이다.
- 진행 중인 타이머에는 저장된 `mode`를 우선 적용한다.
- **`mode`가 없는 기존 활성 타이머는 `countdown`으로 정규화한다.**
- 활성 타이머가 실행 중이거나 멈춘 상태에서는 방식 변경을 막는다.
- 현재 타이머를 저장하거나 취소한 뒤에만 방식 변경이 가능하다.

### 2.1 `mode` 없는 기존 활성 타이머 마이그레이션

기존 활성 타이머에는 카운트다운 기준 필드가 없으므로 다음 절차를 복구 시 한 번 수행한다.

1. 기존 `startedDate`와 `categoryId`를 기준으로 일간 예산을 계산한다.
2. 해당 날짜·대분류의 현재 저장 기록 합계를 계산한다.
3. 기존 타이머의 일시정지 제외 실제 실행시간 `elapsedMs`를 계산한다.
4. 복구 순간 화면에 표시해야 할 값을 다음과 같이 계산한다.

```text
migrationRemainingMs
= (일간 예산 - 현재 저장 기록 합계) × 60,000
```

5. 카운트다운의 기준값은 다음과 같이 저장한다.

```text
initialRemainingMs
= migrationRemainingMs + elapsedMs
```

화면 계산은 항상 아래 식을 사용하므로 마이그레이션 직후 표시값은 `migrationRemainingMs`와 정확히 같다.

```text
표시값 = initialRemainingMs - elapsedMs
```

마이그레이션 결과에는 다음 필드를 저장한다.

```js
{
  mode: 'countdown',
  budgetDate: startedDate,
  initialBudgetMinutes,
  priorRecordedMinutes,
  initialRemainingMs,
  stateChangedAt
}
```

- 원격과 localStorage에 같은 마이그레이션 결과를 저장한다.
- 예산 또는 기록 자료를 아직 불러오지 못했다면 임의의 0으로 변환하지 않고 `예산 계산 중`을 표시한다.
- 계산 자료가 준비되기 전에는 타이머 상태를 삭제하거나 시작·저장하지 않는다.
- 마이그레이션 후부터는 일반 카운트다운과 동일하게 동작한다.

## 3. 카운트업

카운트업은 기존 기능을 유지한다.

- 대분류 선택과 메모 입력
- 타이머 시작
- `멈춤` / `계속`
- `종료하고 저장`
- `취소`
- 일시정지 시간 제외
- localStorage와 Firestore 복구
- 화면 복귀 및 교차 기기 복구
- 오프라인 local-first 저장

카운트다운 추가로 기존 카운트업 계산과 저장 결과가 바뀌어서는 안 된다.

## 4. 카운트다운 시작값

카운트다운에서 대분류를 선택하면 시작 전부터 남은 시간을 표시한다.

```text
시작 시 남은 시간
= 시작 날짜의 일간 예산
- 시작 날짜에 이미 저장된 해당 대분류 기록시간
```

일간 예산은 기존 시간예산 도메인의 우선순위를 그대로 사용한다.

1. 해당 날짜의 직접 일간 예산
2. 주간 예산을 요일 비율로 배분한 값
3. 대분류 기본 예산

기록시간은 서버 기록과 기기의 동기화 대기 기록을 병합한 local-first 기록 집합에서 계산한다. 삭제 기록과 0분 이하 기록은 제외한다.

예시:

```text
오늘 예산 120분
기존 기록 45분
표시값 01:15:00
```

이미 예산을 초과했다면 바로 음수로 표시한다.

```text
오늘 예산 120분
기존 기록 145분
표시값 -00:25:00
```

- 예산 0분, 기록 0분: `00:00:00`
- 예산 0분, 기존 기록 25분: `-00:25:00`
- 자료 로딩 중: `예산 계산 중`, 시작 버튼 비활성화

## 5. 카운트다운 실행과 표시

```text
현재 표시값
= 시작 시 남은 시간
- 이번 타이머의 실제 실행시간
```

멈춘 시간은 실행시간에 포함하지 않는다.

```text
00:00:02
00:00:01
00:00:00
-00:00:01
-00:00:02
```

0 도달 시:

- 알람 없음
- 진동 없음
- 알림창 없음
- 자동 멈춤 없음
- 중단·계속 선택 없음
- 음수 구간으로 끊김 없이 계속 진행

처음부터 음수인 경우도 별도 경고 없이 시작하고 계속 감소한다.

표시 규칙:

- 양수: `HH:MM:SS`
- 0: `00:00:00`
- 음수: `-HH:MM:SS`
- 100시간 이상도 시간 자릿수를 자르지 않는다.
- 절대시각으로 계산하여 백그라운드 복귀 후에도 정확히 표시한다.

## 6. 카운트다운 버튼

실행 중:

```text
[ 멈춤 ] [ 저장 ] [ 취소 ]
```

일시정지 중:

```text
[ 계속 ] [ 저장 ] [ 취소 ]
```

- `멈춤`: 현재 실행 구간을 누적하고 시간을 고정한다.
- `계속`: 멈춘 시간을 제외하고 새 실행 구간을 시작한다.
- `저장`: 실제 실행시간을 기록하고 활성 타이머를 종료한다.
- `취소`: 기록 없이 활성 타이머를 삭제한다.
- 카운트다운은 `저장`, 카운트업은 기존 `종료하고 저장` 문구를 사용한다.

## 7. 대분류 전환

- 카운트다운 실행 중에는 대분류 선택을 잠근다.
- 다른 대분류를 선택하려면 먼저 `멈춤`을 눌러야 한다.
- 멈춘 뒤 다른 대분류를 선택하면 기존 대분류의 이번 실행시간을 자동 저장하고 종료한다.
- 자동 저장 성공 후 새 대분류의 최신 남은 시간을 계산한다.
- 자동 저장 실패 시 전환을 취소하고 기존 멈춘 타이머를 유지한다.
- 이전 대분류를 다시 선택하면 자동 저장 기록을 포함한 최신 남은 시간을 표시한다.

예시:

```text
A 남은 시간 60분
A를 20분 실행 후 멈춤
B 선택 → A의 20분 자동 저장
다시 A 선택 → 남은 시간 40분
```

## 8. 자정 통과

- 예산 기준 날짜는 타이머 시작 날짜로 고정한다.
- 화면 계산도 시작 날짜의 예산과 기록을 기준으로 유지한다.
- 저장 기록의 `date`도 시작 날짜다.
- 자정에 자동 저장·자동 멈춤·다음 날 재시작을 하지 않는다.

## 9. 데이터 모델

기존 `users/{uid}/activeTimer/current` 문서를 확장한다.

공통 필드:

```js
{
  userId,
  categoryId,
  note,
  startedAt,
  startedDate,
  mode,                 // 'countdown' | 'countup'
  accumulatedMs,
  resumedAt,
  pausedAt,
  stateChangedAt,
  running
}
```

카운트다운 전용 필드:

```js
{
  budgetDate,
  initialBudgetMinutes,
  priorRecordedMinutes,
  initialRemainingMs
}
```

```text
initialRemainingMs
= (initialBudgetMinutes - priorRecordedMinutes) × 60,000
```

진행 중 예산이나 외부 기록이 바뀌어도 활성 타이머의 기준값은 갑자기 변경하지 않는다. 타이머가 끝난 뒤 대분류를 다시 선택할 때 최신 예산과 기록으로 다시 계산한다.

## 10. 저장과 초과 처리

카운트다운 저장값은 남은 시간이 아니라 이번 타이머의 실제 실행시간이다.

- 음수 `durationMinutes`를 저장하지 않는다.
- 기존 기록과 동일한 양수 분 단위로 저장한다.
- 기존 최소 1분 저장 규칙을 유지한다.
- 모든 새 타이머 기록에 `timerMode: 'countdown' | 'countup'`을 저장한다.
- 음수 구간까지 실행한 기록은 기존 대시보드와 통계에서 실제 기록 합계가 예산보다 커져 자동으로 초과 처리된다.

예시:

```text
시작 시 남은 예산 30분
실제 실행 45분
저장 기록 45분
예산 초과 15분
```

## 11. 로컬·원격 동기화

- 두 방식 모두 localStorage와 Firestore `activeTimer/current`에 저장한다.
- 시작, 멈춤, 계속, 저장, 취소는 기존 local-first와 트랜잭션 보호를 유지한다.
- 동일한 `startedAt`의 활성 타이머만 갱신하거나 삭제한다.
- 다른 기기의 새 타이머를 오래된 로컬 상태가 덮어쓰지 않는다.
- 재시도 가능한 오류는 로컬 상태를 유지하고 동기화 대기로 처리한다.
- 영구 오류는 상태 변경 전으로 롤백한다.
- 대분류 전환 자동 저장도 일반 저장과 같은 local-first 경로를 사용한다.

## 12. UI와 접근성

- 카드 상단에 같은 너비의 분할 탭을 둔다.
- 순서: `카운트 다운`, `카운트 업`
- 활성 탭은 앱의 주 색상으로 구분한다.
- `role="tab"` 또는 동등한 버튼 구조와 `aria-selected`를 제공한다.
- 활성 타이머가 있으면 다른 방식 탭에 `disabled`, `aria-disabled="true"`를 적용한다.
- 음수는 같은 위치에서 부호를 포함해 표시하되 소리나 팝업은 사용하지 않는다.

## 13. 오류 처리

- 예산 자료가 준비되지 않으면 시작을 막는다.
- 0분 예산은 정상값으로 처리한다.
- 자동 저장 실패 시 대분류 전환을 하지 않는다.
- 복구 실패 시 기존 로컬·원격 자료를 삭제하지 않는다.
- 브라우저의 소리·진동·알림 권한을 요청하지 않는다.

## 14. 테스트 기준

계산:

- 직접 일간 예산 우선
- 주간 예산과 요일 비율 배분
- 서버와 동기화 대기 기록 합산
- 120분 예산, 45분 기록 → 75분
- 120분 예산, 145분 기록 → -25분
- 양수 → 0 → 음수 연속 진행
- 일시정지 동안 값 고정
- 100시간 이상 양수·음수 표시

호환과 복구:

- **`mode` 없는 기존 활성 타이머를 `countdown`으로 변환**
- 변환 직후 표시값이 현재 일간 예산에서 현재 저장 기록을 뺀 값과 일치
- 변환 전 실행시간을 이중 차감하지 않음
- 변환 결과를 localStorage와 Firestore에 저장
- 자료 미로딩 상태에서 임의의 0으로 변환하지 않음
- 카운트다운 일시정지 상태 복원
- 교차 기기의 새 타이머 보호

저장과 UI:

- 음수 구간에서도 양수 실제 실행시간 저장
- 초과 기록이 기존 통계에서 초과로 집계
- 멈춘 뒤 대분류 변경 시 기존 기록 자동 저장
- 자동 저장 실패 시 기존 상태 유지
- 자정 이후에도 시작 날짜로 저장
- 탭 순서 `카운트 다운`, `카운트 업`
- 기본 탭 `카운트 다운`
- 활성 타이머 중 방식 변경 차단
- 실행 중 대분류 선택 잠금
- 카운트다운 버튼 `멈춤/계속`, `저장`, `취소`
- 카운트업 기존 동작 유지
- 0 도달 시 알람·진동·선택창·자동 멈춤 없음

## 15. PWA 배포

- 서비스 워커 셸 캐시 버전을 올린다.
- 새 모듈과 스타일을 앱 셸과 Pages 산출물에 포함한다.
- 전체 테스트와 Pages 검증 통과 후 병합한다.
- `main` 병합으로 GitHub Pages 운영 배포를 실행한다.

## 16. 범위 밖

- 알람, 진동, 시스템 알림
- 0 도달 후 중단·계속 선택창
- 여러 대분류의 멈춘 카운트다운 동시 보관
- 자정 자동 분할 저장
- 사용자 지정 카운트다운 프리셋
