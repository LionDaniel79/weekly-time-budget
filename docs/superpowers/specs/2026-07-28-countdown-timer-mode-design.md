# 카운트다운·카운트업 타이머 설계

## 1. 목표

시간 기록의 타이머 화면에 두 가지 방식을 제공한다.

```text
[ 카운트 다운 ] [ 카운트 업 ]
```

데이터의 방식 값은 다음 순서와 이름을 사용한다.

```text
mode: countdown | countup
```

- **카운트 다운**: 선택한 대분류의 시작 날짜 일간 예산에서 그날 이미 저장된 기록을 뺀 남은 시간을 기준으로 감소한다.
- **카운트 업**: 현재 운영 중인 기존 타이머 기능을 그대로 유지한다.
- 한 사용자에게 동시에 존재할 수 있는 활성 타이머는 현재와 동일하게 하나뿐이다.

## 2. 확정된 사용자 동작

### 2.1 기본 방식과 기존 데이터

- 활성 타이머가 없을 때 타이머 화면의 기본 선택은 `카운트 다운`이다.
- 방식 탭의 화면 순서는 항상 `카운트 다운`, `카운트 업`이다.
- 진행 중인 타이머를 복구하면 저장된 `mode`를 우선 표시한다.
- 기존 활성 타이머처럼 `mode` 필드가 없는 데이터는 `countup`으로 정규화한다.
- 활성 타이머가 실행 중이거나 멈춘 상태에서는 방식 탭을 변경할 수 없다.
- 현재 타이머를 저장하거나 취소한 뒤에만 방식을 변경할 수 있다.

### 2.2 카운트업

카운트업은 기존 동작을 유지한다.

- 대분류 선택
- 메모 입력
- 타이머 시작
- `멈춤` / `계속`
- `종료하고 저장`
- `취소`
- localStorage와 Firestore 복구
- 화면 복귀와 다른 기기 복구
- 멈춘 시간 제외
- 오프라인 local-first 처리

카운트다운 추가 때문에 기존 카운트업 계산, 저장 형식, 버튼 동작을 변경하지 않는다.

### 2.3 카운트다운 대분류 선택

카운트다운에서 대분류를 선택하면 시작 버튼을 누르기 전부터 남은 시간을 자동으로 표시한다.

```text
시작 시 남은 시간
= 시작 날짜의 일간 예산
- 시작 날짜에 이미 저장된 해당 대분류 기록시간
```

일간 예산은 기존 시간예산 도메인의 계산을 그대로 사용한다.

1. 해당 날짜의 직접 일간 예산이 있으면 그 값을 사용한다.
2. 직접 일간 예산이 없으면 주간 예산과 요일 비율로 배분된 값을 사용한다.
3. 주간 문서에 값이 없으면 기존 대분류 기본 예산을 사용한다.

기록시간은 서버 기록과 기기에 저장된 동기화 대기 기록을 병합한 현재 앱의 local-first 기록 집합을 사용한다. 삭제된 기록과 0분 이하 기록은 포함하지 않는다.

예시:

```text
오늘 예산 120분
오늘 기존 기록 45분
표시값 01:15:00
```

이미 예산을 초과했다면 음수로 바로 표시한다.

```text
오늘 예산 120분
오늘 기존 기록 145분
표시값 -00:25:00
```

예산이 0분이고 기존 기록이 없다면 `00:00:00`을 표시한다. 예산이 0분인데 기존 기록이 있다면 그 기록만큼 음수로 표시한다.

예산과 기록 자료가 아직 로드되지 않았다면 `예산 계산 중`을 표시하고 시작 버튼을 비활성화한다. 캐시나 서버 자료가 준비된 뒤 계산 결과를 표시한다.

### 2.4 카운트다운 실행

카운트다운 시작 후 화면 값은 다음과 같이 계산한다.

```text
현재 표시값
= 시작 시 남은 시간
- 이번 타이머의 실제 실행시간
```

멈춘 시간은 실제 실행시간에 포함하지 않는다.

```text
01:15:00
01:14:59
...
00:00:01
00:00:00
-00:00:01
-00:00:02
```

0에 도달했을 때의 확정 동작:

- 알람을 울리지 않는다.
- 진동을 사용하지 않는다.
- 알림창을 표시하지 않는다.
- 자동으로 멈추지 않는다.
- `중단` 또는 `계속` 선택을 요구하지 않는다.
- 그대로 음수 구간으로 계속 진행한다.

처음부터 음수인 대분류도 별도 경고 없이 즉시 음수 값에서 시작하고 계속 감소한다.

### 2.5 카운트다운 버튼

실행 중:

```text
[ 멈춤 ] [ 저장 ] [ 취소 ]
```

일시정지 중:

```text
[ 계속 ] [ 저장 ] [ 취소 ]
```

- `멈춤`: 현재 실행 구간을 누적하고 시간을 고정한다.
- `계속`: 멈춘 시각 이후의 대기시간을 제외하고 새 실행 구간을 시작한다.
- `저장`: 이번 카운트다운의 실제 실행시간을 시간 기록으로 저장하고 활성 타이머를 종료한다.
- `취소`: 이번 실행을 기록하지 않고 활성 타이머를 삭제한다.

카운트다운에서 `저장` 버튼 문구는 `종료하고 저장`이 아니라 `저장`으로 표시한다. 카운트업의 기존 `종료하고 저장` 문구는 유지한다.

### 2.6 대분류 전환

- 카운트다운이 실행 중일 때 대분류 선택을 잠근다.
- 다른 대분류를 선택하려면 먼저 `멈춤`을 눌러야 한다.
- 멈춘 뒤 다른 대분류를 선택하면 기존 대분류의 이번 실행시간을 자동 저장하고 기존 활성 타이머를 종료한다.
- 자동 저장이 성공한 뒤 새 대분류를 선택하고 남은 예산을 다시 계산한다.
- 자동 저장에 실패하면 대분류 전환을 취소하고 기존 멈춘 타이머를 유지한다.
- 이전 대분류를 나중에 다시 선택하면 자동 저장된 기록까지 포함해 최신 남은 시간을 다시 계산해 표시한다.

예시:

```text
A 대분류 남은 시간 60분
A를 20분 실행 후 멈춤
B 선택 → A의 20분 자동 저장
다시 A 선택 → 남은 시간 40분 표시
```

### 2.7 자정 통과

카운트다운이 자정을 지나도 시작 날짜에 계속 연결한다.

- 예산 기준 날짜는 타이머를 시작한 날짜로 고정한다.
- 화면 계산도 시작 날짜의 예산과 기존 기록을 기준으로 유지한다.
- 저장되는 기록의 `date`도 시작 날짜를 사용한다.
- 자정에 자동 저장, 자동 멈춤, 다음 날 타이머 재시작을 하지 않는다.

## 3. 데이터 모델

기존 `users/{uid}/activeTimer/current` 문서를 확장한다.

### 3.1 공통 필드

```js
{
  userId,
  categoryId,
  note,
  startedAt,
  startedDate,
  mode,                 // 'countdown' | 'countup'
  accumulatedMs,
  resumedAt,
  pausedAt,
  stateChangedAt,
  running
}
```

기존 일시정지·복구 필드는 두 방식에서 공통으로 사용한다.

### 3.2 카운트다운 전용 필드

```js
{
  budgetDate,           // 시작 날짜. startedDate와 동일하게 유지
  initialBudgetMinutes, // 시작할 때 계산한 일간 예산
  priorRecordedMinutes, // 시작 전에 이미 저장돼 있던 해당 날짜·대분류 기록
  initialRemainingMs    // (initialBudgetMinutes - priorRecordedMinutes) * 60000
}
```

카운트다운 표시값은 저장된 `initialRemainingMs`와 현재 타이머의 실제 실행시간으로 계산한다. 실행 중 예산이나 다른 기록이 외부에서 바뀌어도 진행 중인 타이머의 기준값은 갑자기 변하지 않는다.

활성 타이머가 끝난 뒤 대분류를 다시 선택하면 최신 예산과 기록으로 새 기준값을 계산한다.

### 3.3 정규화

- `mode`가 없으면 `countup`으로 처리한다.
- `mode`가 `countdown`인데 필수 기준 필드가 없거나 숫자가 아니면 원격·로컬 자료에서 임의로 추정하지 않는다.
- 복구 시 필요한 예산 자료를 다시 조회할 수 있으면 동일한 `budgetDate`와 `categoryId`로 기준값을 복구한다.
- 복구할 수 없으면 타이머를 실행하지 않고 오류 안내를 표시하며 원본 문서는 삭제하지 않는다.
- 음수 `initialRemainingMs`는 정상 값으로 인정한다.

## 4. 표시 계산

### 4.1 공통 실제 실행시간

기존 타이머의 실제 실행시간 계산을 그대로 사용한다.

```text
실행 중 실제 시간
= accumulatedMs + (현재시각 - resumedAt)

일시정지 실제 시간
= accumulatedMs
```

### 4.2 카운트다운 표시값

```text
remainingMs = initialRemainingMs - elapsedMs
```

표시 규칙:

- `remainingMs > 0`: `HH:MM:SS`
- `remainingMs = 0`: `00:00:00`
- `remainingMs < 0`: `-HH:MM:SS`
- 음수 부호는 시간 문자열 맨 앞에 한 번만 표시한다.
- 100시간 이상도 잘리지 않도록 시간 자릿수는 고정 두 자리로 제한하지 않는다.

초 단위 화면은 절대시각 기반으로 계산하여 브라우저가 백그라운드에서 인터벌을 늦게 실행해도 복귀 시 정확한 값을 표시한다.

## 5. 저장과 초과 처리

카운트다운을 저장할 때 저장되는 `durationMinutes`는 이번 타이머의 실제 실행시간이다.

```text
저장시간 = 멈춘 구간을 제외한 실제 실행시간
```

- 남은 예산 값 자체를 기록하지 않는다.
- 음수 시간을 음수 `durationMinutes`로 저장하지 않는다.
- 기존 시간 기록과 동일하게 양수 분 단위 기록으로 저장한다.
- 기존 타이머와 같은 최소 1분 저장 규칙을 유지한다.
- 새 타이머 기록은 기존 `source: 'timer'`를 유지하고, 카운트업과 카운트다운 모두 `timerMode`에 실제 방식 값(`countup` 또는 `countdown`)을 저장한다.
- 과거 기록처럼 `timerMode`가 없는 기록은 기존 통계와 동일하게 처리한다.
- 대시보드와 통계는 저장된 실제 기록 합계와 예산을 비교하므로 음수 구간까지 실행해 저장하면 자동으로 초과 상태가 된다.

예시:

```text
시작 시 남은 예산 30분
실제 실행 45분
저장 기록 45분
예산 초과 15분
```

## 6. 로컬·원격 동기화와 교차 기기

- 카운트다운도 기존 타이머와 동일하게 localStorage와 Firestore `activeTimer/current`에 저장한다.
- 시작, 멈춤, 계속, 저장, 취소는 현재의 local-first·트랜잭션 보호 원칙을 유지한다.
- 다른 기기에서 시작된 새 타이머를 오래된 로컬 타이머가 덮어쓰지 않는다.
- 동일한 `startedAt`의 같은 활성 타이머만 멈춤·계속·삭제할 수 있다.
- 원격 연결 실패가 재시도 가능하면 로컬 상태를 유지하고 사용자에게 동기화 대기 상태를 알린다.
- 영구 오류이면 상태 변경 전으로 롤백한다.
- 대분류 전환 자동 저장도 일반 저장과 동일한 local-first 저장 경로를 사용한다.

## 7. UI 구조

타이머 카드 상단에 방식 선택 탭을 둔다.

```text
┌─────────────────────────────┐
│ [ 카운트 다운 ] [ 카운트 업 ] │
│                             │
│ 대분류                       │
│ 메모                         │
│                             │
│         01:15:00            │
│                             │
│ [멈춤] [저장] [취소]          │
└─────────────────────────────┘
```

- 선택 탭은 첨부 사진처럼 두 개의 동일한 폭을 가진 분할 버튼 형태로 표시한다.
- 활성 탭은 현재 앱의 주 색상으로 명확히 구분한다.
- 키보드와 스크린리더를 위해 버튼 또는 `role="tab"` 구조와 `aria-selected`를 사용한다.
- 모바일과 데스크톱에서 같은 순서를 유지한다.
- 실행 중이거나 멈춘 타이머가 있으면 비활성 탭에 `disabled`와 `aria-disabled="true"`를 적용한다.
- 카운트다운의 양수·0·음수는 같은 자리에서 표시하며, 음수는 시각적으로 구분하되 경고창이나 소리는 사용하지 않는다.

## 8. 오류 처리

- 예산 계산 자료가 준비되지 않으면 시작을 막고 `오늘 예산을 불러오는 중입니다.`를 표시한다.
- 대분류에 대응하는 예산이 계산 가능하면 0분도 정상 예산으로 취급한다.
- 자동 저장 후 대분류 전환 중 저장 실패가 발생하면 새 대분류로 넘어가지 않는다.
- 활성 카운트다운 복구 실패 시 기존 로컬·원격 자료를 삭제하지 않는다.
- 서로 다른 기기의 활성 타이머 충돌은 현재 타이머 충돌 안내 경로를 사용한다.
- 브라우저의 소리 재생 권한이나 알림 권한을 요청하지 않는다.

## 9. 테스트 기준

### 9.1 계산 도메인

- 직접 일간 예산을 우선 적용한다.
- 주간 예산과 요일 비율로 일간 예산을 계산한다.
- 기존 서버 기록과 동기화 대기 기록을 합산한다.
- 예산 120분, 기존 기록 45분이면 75분을 반환한다.
- 예산 120분, 기존 기록 145분이면 -25분을 반환한다.
- 예산 0분과 기록 0분이면 0을 반환한다.
- 양수 → 0 → 음수로 끊김 없이 진행한다.
- 멈춘 동안 표시값이 변하지 않는다.
- 계속 후 새 실행 구간만 차감한다.
- 100시간 이상의 양수·음수 값을 올바르게 표시한다.

### 9.2 저장

- 음수 구간에서도 저장 기록은 양수 실제 실행시간이다.
- 새 카운트업·카운트다운 기록에 정확한 `timerMode`를 저장한다.
- 과거 `timerMode` 없는 기록의 통계 동작은 바뀌지 않는다.
- 음수 구간의 실행분이 기존 대시보드에서 초과로 집계된다.
- 다른 대분류 선택 시 멈춘 기존 카운트다운을 자동 저장한다.
- 자동 저장 실패 시 기존 타이머와 대분류 선택을 유지한다.
- 자정 이후 저장해도 시작 날짜로 기록한다.

### 9.3 호환과 복구

- `mode` 없는 기존 타이머는 카운트업으로 복원한다.
- 카운트다운의 일시정지 상태를 앱 재실행 후 복원한다.
- 화면 복귀 시 절대시각으로 음수 값을 재계산한다.
- 다른 기기의 새 타이머를 오래된 로컬 자료가 덮어쓰지 않는다.
- 오프라인에서 멈춤·계속·저장이 local-first로 유지된다.

### 9.4 UI

- 탭 순서가 `카운트 다운`, `카운트 업`이다.
- 활성 타이머가 없을 때 기본 탭은 카운트다운이다.
- 기존 활성 타이머는 저장된 방식으로 표시한다.
- 실행 중·멈춤 중 방식 변경이 차단된다.
- 카운트다운 실행 중 대분류 선택이 잠긴다.
- 카운트다운 일시정지 후 대분류 선택이 가능하다.
- 카운트다운 버튼 문구는 `멈춤/계속`, `저장`, `취소`이다.
- 카운트업 버튼과 동작은 기존과 동일하다.
- 0 도달 시 알람·진동·선택창·자동 멈춤 코드가 실행되지 않는다.

## 10. PWA 배포

- 변경된 타이머 도메인, UI, 스타일이 설치형 웹앱에 반영되도록 서비스 워커 셸 캐시 버전을 올린다.
- 새로 추가되는 모듈이나 스타일은 앱 셸 캐시와 Pages 산출물에 포함한다.
- 전체 테스트, Pages 아티팩트 생성, 필수 파일 검사를 통과한 뒤 병합한다.
- `main` 병합 후 기존 GitHub Pages 배포 워크플로로 운영 배포한다.

## 11. 범위 밖

이번 구현에는 다음을 포함하지 않는다.

- 알람, 진동, 시스템 알림
- 0 도달 후 중단·계속 선택창
- 여러 대분류의 멈춘 카운트다운 동시 보관
- 자정 기준 자동 분할 저장
- 카운트다운 프리셋 직접 입력
- 카테고리별 알림음 설정
- 백그라운드 OS 알림 서비스
