# 통계 서브시스템 재구성 설계

작성일: 2026-08-01  
대상 브랜치: `fix/statistics-subsystem-refactor`

## 1. 배경

운영 웹앱에서 주별·연간·월간 비교·연도별 비교는 동작하지만, `월간 통계` 탭을 누르면 화면이 멈추는 현상이 반복되고 있다. 이전 수정에서는 각각 다음 경로를 차단했다.

- 0분 통계의 DOM 후처리와 `MutationObserver` 반복
- 신·구 통계 렌더러 동시 실행
- 기록 기간 모듈의 월 선택 DOM 중복 소유
- 오래된 PWA 셸과 새 자산 혼합

그러나 실제 기기에서는 문제가 계속된다. 현재 테스트는 대부분 소스 문자열과 순수 계산 함수를 검사하며, 브라우저에서 통계 메뉴와 월간 탭을 실제로 클릭하는 흐름을 실행하지 않는다. 따라서 기존 CI 성공은 실제 멈춤이 제거되었음을 증명하지 못했다.

이번 작업은 조건문을 하나 더 추가하는 방식이 아니라, 통계 화면의 데이터·상태·기간 이동·렌더링·이벤트 소유권을 하나로 정리하고 실제 브라우저 재현 테스트를 도입하는 집중 리팩터링이다.

## 2. 현재 구조와 확인된 문제

### 2.1 현재 통계 주 실행 경로

현재 `index.html`은 `statistics-offline-rescue.js`를 주 통계 렌더러로 실행한다. 이 모듈은 다음 책임을 동시에 가진다.

- IndexedDB 캐시 우선 조회
- Firestore 최신 자료 조회와 8초 제한시간
- 통계 상태 보관
- 통계 탭 전환
- 주·연·월 선택
- 기간 집계 호출
- 통계 HTML 생성
- 통계 화면 전체 `innerHTML` 교체
- 통계 상태 저장·복원

### 2.2 통계 화면을 건드리는 다른 경로

`recorded-period-navigation.js`도 통계 화면에 다음 작업을 수행한다.

- 주간 통계 이전·다음 기록 주 탐색
- 통계 버튼 활성·비활성 보정
- 0분 목표 준수 문구 DOM 후처리
- 기록 기간 인덱스 갱신
- `document.body` 전체 `MutationObserver`
- 과거 월 선택 보정용 함수와 이벤트 처리

최근 수정으로 현재 통계 렌더러에서 일부 월간 보정은 조기 종료하지만, 통계 관련 코드와 감시 경로 자체는 남아 있다.

### 2.3 불필요하거나 오래된 코드

다음 파일은 현재 HTML에서 통계 렌더러로 실행되지 않지만 저장소와 Pages 산출물에 남아 있다.

- `src/statistics-ui.js`
- `src/statistics-session-state.js`

`src/statistics-mobile-overflow.js`는 자바스크립트 파일이지만 실제 역할은 CSS 삽입뿐이다. 통계 공용 CSS 파일이 이미 존재하므로 별도 런타임 스크립트가 필요하지 않다.

### 2.4 검증 공백

현재 `npm test`는 Node 테스트만 실행한다. 실제 브라우저에서 다음 흐름을 검증하지 않는다.

1. 로그인된 상태로 통계 메뉴 클릭
2. 월간 통계 클릭
3. 연도·월 선택 생성
4. 통계 집계 및 렌더 완료
5. 주간과 월간 반복 전환
6. 이벤트 루프가 계속 반응하는지 확인
7. 브라우저 콘솔 오류와 처리되지 않은 Promise 확인

이 검증 공백 때문에 DOM 반복, 합성 이벤트 재진입, 메인 스레드 장기 점유를 CI가 탐지하지 못한다.

## 3. 문제 범위 판단

### 3.1 가능성이 낮은 단독 원인

`월간 통계`가 호출하는 `summarizeRecordedMonthlyBudgetPeriod()`는 연간 통계와 월간 비교에서도 재사용된다. 다른 통계가 정상이라는 사용자 관찰을 고려하면, 월간 집계 함수 하나만이 유일한 원인일 가능성은 낮다.

다만 특정 데이터 크기나 형태에서 월간 집계가 과도하게 반복 호출되는 경우는 별개이므로 브라우저 계측으로 확인한다.

### 3.2 가장 의심되는 경계

월간 통계에만 추가되는 다음 흐름을 핵심 조사 범위로 한다.

- 월간 탭 상태 변경
- 연도·월 선택 모델 생성
- 전체 통계 DOM 교체
- 상태 저장 이벤트
- 상태 복원 이벤트
- 기록 기간 모듈과 전역 감시자 반응
- 같은 데이터에 대한 중복 월간 집계·렌더

정적 분석만으로 마지막 한 줄의 원인을 확정하지 않는다. 먼저 실제 브라우저 테스트에서 멈춤 또는 과도한 반복을 재현하고, 호출 횟수와 소요 시간을 계측한 뒤 원인을 확정한다.

## 4. 목표

1. 실제 브라우저에서 월간 통계 멈춤을 재현하는 실패 테스트를 만든다.
2. 통계 화면 `#statistics-view`의 DOM·상태·이벤트를 하나의 통계 기능만 소유하게 한다.
3. 월간 탭 전환은 서버 재조회 없이 이미 적재된 자료로 한 번 집계하고 한 번 렌더한다.
4. 기록이 없는 과거 월과 미래 월은 최초 렌더 단계에서 비활성화한다.
5. 상태 복원은 합성 클릭이나 합성 `change` 이벤트 없이 상태값을 직접 적용한다.
6. 통계 화면을 대상으로 하는 전역 `MutationObserver` 후처리를 제거한다.
7. 사용하지 않는 과거 통계 코드와 런타임 CSS 주입 코드를 제거한다.
8. 빈 계정, 일반 계정, 기록이 많은 계정, 보관·절제·기존 대분류가 섞인 계정에서 통계를 검증한다.
9. 구형 PWA 설치본에서 새 통계 구조로 안전하게 갱신되는지 검증한다.

## 5. 비목표

- 대시보드, 시간 예산, 타이머, 기록 저장 방식의 전면 재작성
- Firebase 데이터 구조 변경
- 목표 준수 계산식 변경
- 성장·절제 목표의 의미 변경
- 통계 화면의 시각 디자인 전면 개편
- 앱 전체의 모든 `MutationObserver`를 한 번에 제거하는 대규모 리팩터링

통계 수정에 직접 영향을 주는 감시 경로만 제거하거나 범위를 제한한다.

## 6. 권장 구조

### 6.1 단일 통계 기능 모듈

새 `src/statistics-feature.js`가 통계 화면의 유일한 실행 진입점이 된다.

책임:

- 인증 사용자 전환 처리
- 캐시 우선 자료 적재
- 서버 백그라운드 갱신과 제한시간
- 통계 상태 관리
- 탭·기간 컨트롤 이벤트 처리
- 기록 기간 선택 모델 계산
- 통계 집계 호출
- 통계 HTML 생성 및 반영
- 상태 저장·복원
- 오류 경계와 재시도

`index.html`에서는 통계 기능 스크립트를 이 파일 하나만 실행한다.

### 6.2 데이터 적재 경계

통계 기능 내부에서 데이터 적재와 UI 상태를 논리적으로 분리한다.

```text
StatisticsData
- entries
- activeCategories
- archivedCategories
- weeklyBudgets
- revision
- source: cache | server

StatisticsViewState
- mode
- weekStart
- year
- month
- loading
- warning
- errorStage
```

캐시 또는 서버 자료가 바뀔 때만 `revision`이 증가한다. 탭 전환은 자료를 다시 읽지 않고 현재 `StatisticsData`를 사용한다.

### 6.3 DOM 소유권

`#statistics-view` 내부 DOM은 `statistics-feature.js`만 생성·교체한다.

다른 모듈은 다음을 하지 않는다.

- 통계 컨트롤 옵션 재생성
- 통계 문구 후처리
- 통계 버튼 합성 클릭
- 통계 `change` 합성 이벤트
- 통계 화면을 기준으로 한 DOM 감시·보정

통계 상태 변경은 명시적 이벤트 핸들러에서만 발생한다.

### 6.4 기록 기간 선택

`recorded-period-domain.js`의 순수 함수는 계속 사용한다. 통계 기능이 현재 적재 자료로 기록 기간 인덱스를 만들고 직접 다음을 계산한다.

- 가장 가까운 이전·다음 기록 주
- 선택 가능한 연도
- 기록이 있는 월
- 이번 달
- 기록 없는 과거 월과 미래 월의 비활성 상태
- 저장된 월이 무효할 때 사용할 대체 월

`recorded-period-navigation.js`에는 대시보드 기간 이동만 남긴다. 파일명 변경은 이번 작업 범위에 포함하지 않는다. 통계 책임만 제거해 변경 범위를 제한한다.

### 6.5 월간 통계 전환

월간 탭 클릭은 다음 순서로만 실행한다.

```text
1. mode = monthly
2. 현재 year/month를 기록 기간 모델로 정규화
3. 월간 요약을 한 번 계산
4. 통계 HTML을 한 번 생성
5. #statistics-view에 한 번 반영
6. 정규화된 상태를 한 번 저장
```

월간 탭 클릭에서 서버 조회를 시작하지 않는다. 서버 자료 갱신은 통계 메뉴 최초 진입, 명시적 다시 불러오기, 통계가 열린 상태의 실제 데이터 변경 이벤트에서만 수행한다.

### 6.6 0분 목표 준수 표시

렌더 이후 `patchZeroAchievement()`로 DOM을 수정하지 않는다.

요약 표시 함수를 다음 규칙으로 만든다.

- 기간 예산 0분이고 실제 기록 0분: `—`
- 계산 대상 예산이 없음: `계산 제외`
- 그 외: `N점`

최초 HTML에 최종 문자열을 넣으므로 후처리와 감시 반복이 없다.

### 6.7 렌더 중복 방지

통계 기능은 렌더 서명을 사용한다.

```text
renderSignature = dataRevision + mode + weekStart + year + month + source + warning
```

서명이 이전 렌더와 같으면 DOM을 다시 쓰지 않는다. 이는 정상 탭 전환을 막는 전역 플래그가 아니라 동일 입력의 중복 렌더만 제거한다.

### 6.8 오류 경계

통계 처리 단계를 구분한다.

- `cache-read`
- `server-read`
- `period-model`
- `aggregate`
- `render`
- `state-persist`

집계나 렌더에서 예외가 발생하면 앱 전체를 멈추지 않고 통계 화면 안에 다음을 표시한다.

- 통계를 표시하지 못했다는 안내
- 실패 단계
- 다시 시도 버튼

오류 객체 전체나 사용자 데이터는 화면에 노출하지 않는다. 개발자 콘솔에는 단계와 오류를 기록한다.

## 8. 브라우저 재현 및 검증 설계

### 8.1 Playwright 도입

Node 문자열 테스트를 유지하되, Playwright 기반 브라우저 통합 테스트를 추가한다.

통계 기능은 테스트에서 인증과 Firestore에 직접 의존하지 않도록 자료 적재 인터페이스를 주입할 수 있게 구성한다. 테스트 전용 HTML 또는 전체 앱 테스트 진입점에서 고정 자료를 제공한다.

운영 코드는 실제 캐시·Firestore 적재기를 사용하고, 브라우저 테스트는 결정적인 메모리 적재기를 사용한다.

### 8.2 필수 데이터 시나리오

1. 완전 빈 계정
2. 현재 달 기록만 있는 계정
3. 여러 해의 기록과 주간 예산이 있는 계정
4. 보관 대분류가 있는 계정
5. `createdDate`가 없는 기존 대분류와 새 대분류가 함께 있는 계정
6. 성장 목표와 절제 목표가 함께 있는 계정
7. 기록 없는 과거 월과 미래 월이 존재하는 선택 모델
8. 대표 대용량 자료: 여러 해, 다수 대분류, 수천 건 기록

### 8.3 브라우저 동작 테스트

각 시나리오에서 다음을 검증한다.

- 통계 메뉴 진입
- 월간 통계 클릭
- 월간 탭 활성 표시
- 선택된 연도·월 표시
- 통계 카드와 표 렌더 완료
- 주간 → 월간 → 연간 → 월간 비교 → 월간 전환
- 주간 ↔ 월간 20회 반복
- 클릭 이후 브라우저가 계속 반응함
- 처리되지 않은 예외 없음
- 콘솔 오류 없음
- 한 클릭당 월간 집계와 렌더가 각각 한 번만 실행됨

테스트는 특정 CSS 문자열 존재가 아니라 실제 사용자 동작과 최종 DOM을 검사한다.

### 8.4 성능 관찰

실패 재현 단계에서 임시 계측으로 다음 횟수와 시간을 기록한다.

- 탭 클릭 처리 횟수
- 상태 저장 횟수
- 월간 집계 호출 횟수와 소요 시간
- 렌더 호출 횟수와 소요 시간
- 데이터 조회 시작 횟수
- 상태 복원 횟수

원인을 확인한 뒤 제품에 불필요한 임시 계측 코드는 제거한다. 최종 브라우저 테스트에서는 반복 횟수와 렌더 횟수를 직접 검증한다.

## 9. PWA 갱신

- 새 서비스 워커 셸 버전을 사용한다.
- 새 `statistics-feature.js`와 통합 CSS를 셸 캐시에 포함한다.
- 삭제한 통계 파일은 셸 캐시에서 제외한다.
- v13, v14, v15 셸이 남아 있는 설치본에서 새 버전으로 갱신되는 테스트를 추가한다.
- 제어권 변경 후 한 번만 새로고침되는 기존 규칙을 유지한다.
- 운영 화면에 빌드 식별자를 추가하는 것은 진단에 필요할 경우 통계 오류 화면 또는 개발자용 메타 정보로 제한하며, 일반 UI에는 불필요하게 노출하지 않는다.

## 10. 구현 순서

1. Playwright와 통계 테스트 적재기 도입

14. 구형 PWA 업그레이드 검증

## 11. 완료 기준

다음 항목이 모두 충족되어야 완료로 판단한다.

- 현재 문제를 재현하는 브라우저 실패 테스트가 수정 전 RED로 확인됨
- 수정 후 빈 계정과 기록 계정 모두 월간 통계가 열림
- 주간 ↔ 월간 20회 반복 후에도 화면과 메뉴가 반응함
- 브라우저 콘솔 오류와 처리되지 않은 Promise가 없음
- 한 탭 클릭에 월간 집계와 렌더가 각각 한 번만 실행됨
- 월간 탭 전환이 Firestore 전체 재조회를 시작하지 않음
- 기록 없는 과거 월과 미래 월이 비활성화됨
- 저장된 무효 월은 가장 가까운 유효 월 또는 이번 달로 한 번만 보정됨
- 주간·연간·월간 비교·연도별 비교 결과가 유지됨
- 목표 준수, 생성일, 보관 대분류, 절제 목표 계산이 기존 순수 테스트와 일치함
- 통계 DOM을 수정하는 전역 `MutationObserver`가 없음
- 사용하지 않는 과거 통계 파일이 저장소·HTML·서비스 워커·Pages 검사에서 제거됨
- 전체 Node 테스트, Playwright 테스트, Pages 산출물 검사가 성공함
- 구형 PWA 설치본의 새 셸 전환 테스트가 성공함

## 12. 위험과 대응

### 통계 상태 복원 회귀

합성 클릭 기반 복원을 제거하면 기존 저장 상태가 누락될 수 있다. `ui-session-state.js`의 기존 상태 형식을 유지하고, 통계 기능 초기화 시 정규화된 상태를 직접 적용하는 회귀 테스트를 둔다.

### 기록 기간 이동 회귀

통계 주 이동과 월 활성화 책임을 옮길 때 대시보드 이동이 영향을 받을 수 있다. `recorded-period-navigation.js`의 대시보드 테스트와 새 통계 기간 테스트를 분리한다.

### 오프라인 통계 회귀

캐시 우선 표시와 서버 제한시간은 유지한다. 빈 캐시·서버 실패, 캐시 성공·서버 실패, 캐시 성공·서버 성공, 사용자 전환을 각각 테스트한다.

### 리팩터링 범위 확대

안정된 순수 통계 계산 API는 브라우저 재현 결과가 성능 문제를 가리키지 않는 한 유지한다. 앱 전체 감시자 제거와 도메인 파일 대규모 분리는 별도 작업으로 남긴다.
