# Sunday Calendar and Category Layout Design

## Goal

두 가지 UI 문제를 최소 범위로 수정한다.

1. 대시보드 일간 캘린더를 월요일 시작에서 일요일 시작으로 변경한다.
2. 대분류 관리 화면에서 등록된 대분류 목록이 절반 폭에 눌리지 않도록 전체 폭 레이아웃으로 재구성한다.

## Calendar behavior

- 캘린더 요일 헤더는 `일 월 화 수 목 금 토` 순서로 표시한다.
- 월 첫째 날의 빈 셀 계산도 일요일 시작 기준으로 변경한다.
- 날짜 선택 가능 여부, 오늘 표시, 이전/다음 달 이동 규칙은 변경하지 않는다.
- 주간 예산과 통계의 주 시작 규칙(월요일~일요일)은 변경하지 않는다. 이번 변경은 일간 대시보드의 달력 표현에만 적용한다.

## Category management layout

데스크톱에서 다음 순서로 세로 배치한다.

1. `대분류 추가` 카드
2. `등록된 대분류` 카드 — 전체 콘텐츠 폭 사용
3. `보관된 대분류` 카드 — 존재할 때 전체 콘텐츠 폭 사용

등록된 대분류 행은 현재 이름 입력과 `수정 / 보관 / 삭제` 동작을 유지한다. 화면 폭이 좁아질 때는 기존 모바일 규칙대로 버튼 영역이 아래로 내려가도록 한다.

기능 동작, 대분류 저장/보관/삭제 로직, 절제 목표 표시 방식은 변경하지 않는다.

## Implementation boundaries

- `src/time-budget-domain.js`: 캘린더 셀 오프셋을 일요일 기준으로 변경.
- `src/time-budget-ui.js`: 요일 헤더 순서를 일요일부터 시작하도록 변경.
- `src/category-feature.js`: 대분류 관리 마크업에 전용 레이아웃 클래스를 부여하고 세 카드의 구조를 전체 폭 세로 배치로 변경.
- `styles.css`: 대분류 관리 전용 레이아웃 스타일 추가. 다른 `.grid-2` 화면에는 영향이 없어야 한다.

## Testing

- Node 회귀 테스트로 일요일 시작 캘린더 셀 위치를 고정한다.
- UI/source 계약 테스트로 요일 헤더가 `일~토` 순서임을 확인한다.
- 대분류 화면 계약 테스트로 등록/보관 카드가 전용 전체 폭 레이아웃을 사용함을 확인한다.
- 기존 Node 전체 테스트와 Chromium Playwright 테스트가 모두 통과해야 한다.

## Non-goals

- 주간 기간 계산을 일요일 시작으로 변경하지 않는다.
- 대분류 정렬, 검색, 드래그 앤 드롭 같은 새 기능을 추가하지 않는다.
- 대분류 삭제/보관 데이터 모델을 변경하지 않는다.
