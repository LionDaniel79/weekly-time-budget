# 오프라인 기록 동기화·저장 확인·화면 복원 설계

## 1. 목표

인터넷이 없거나 연결이 불안정해도 수동 입력과 타이머 기록을 잃지 않고 저장한다. 기록은 기기에 먼저 안전하게 보관하고, 연결이 회복되면 자동으로 Firestore에 반영한다. 사용자는 `기록 저장` 또는 `종료하고 저장` 직후 서버 저장 완료인지 동기화 대기 상태인지 화면 아래 알림 배너로 확인할 수 있다. 앱을 다시 열면 마지막으로 사용한 메뉴와 그 메뉴의 내부 탭·기간을 복원한다.

## 2. 확정 요구사항

- 오프라인 사용은 이 기기에서 이전에 로그인한 동일 사용자만 허용한다.
- 로그인하지 않은 임시 사용자 기록은 만들지 않는다.
- 수동 입력과 타이머 기록 모두 오프라인 저장을 지원한다.
- 기록 저장 직후 대시보드와 기록 내역에 즉시 반영한다.
- 서버에 아직 반영되지 않은 기록은 `동기화 대기`로 표시한다.
- 앱 시작, 인터넷 재연결, 앱이 다시 보이게 될 때 자동 동기화한다.
- 같은 기록이 두 번 서버에 저장되지 않게 한다.
- 저장 결과는 확인 버튼이 없는 화면 아래 알림 배너로 3~5초간 표시한다.
- 앱을 다시 열면 마지막 사이드 메뉴와 내부 탭·선택 기간을 복원한다.
- iOS에서 지원이 일정하지 않은 Background Sync API에는 의존하지 않는다.

## 3. 권장 구조

### 3.1 서비스 워커

`service-worker.js`를 추가하고 `index.html`에서 등록한다.

서비스 워커는 다음 파일을 버전이 붙은 앱 셸 캐시에 저장한다.

- `index.html`
- `styles.css`
- `manifest.webmanifest`
- `src/` 아래 실행 모듈
- 아이콘
- 최초 온라인 실행 중 실제로 불러온 Firebase CDN 모듈

정적 앱 파일은 캐시 우선 후 백그라운드 갱신 방식으로 제공한다. Firestore 문서 요청과 인증 API 응답은 서비스 워커 캐시에 넣지 않는다. 네트워크가 끊겼을 때 페이지 이동 요청은 캐시된 `index.html`로 대체한다.

이 설계는 앱을 한 번 이상 정상적으로 온라인 실행한 기기에서 이후 오프라인 재실행이 가능하도록 한다. 처음 방문하는 기기에서 인터넷 없이 앱을 설치하거나 로그인하는 것은 지원하지 않는다.

### 3.2 IndexedDB 저장소

새 모듈 `src/offline-store.js`가 IndexedDB 접근을 전담한다. 데이터베이스 이름은 `weekly-time-budget-offline`, 버전은 1로 시작한다.

객체 저장소:

1. `pendingEntries`
   - key: `localId`
   - 필드: `localId`, `userId`, `entry`, `status`, `attempts`, `createdAt`, `lastAttemptAt`, `clearActiveTimer`
2. `userSnapshots`
   - key: `userId`
   - 필드: 마지막 정상 조회 시점의 활성 대분류, 보관 대분류, 최근 기록, 주간 예산, 일간 예산, 기본 요일 비율, `updatedAt`
3. `uiState`
   - key: `userId`
   - 필드: 마지막 메뉴와 각 화면의 내부 상태

모든 데이터는 `userId`로 분리한다. 로그아웃하면 오프라인 데이터 자체는 삭제하지 않지만 앱 화면에서는 숨긴다. 같은 사용자가 다시 로그인했을 때만 대기 기록과 화면 상태를 복원한다.

IndexedDB 쓰기 자체가 실패하면 기록 저장 성공으로 안내하지 않는다. 입력값을 유지한 채 오류 배너를 표시한다.

## 4. 기록 저장 흐름

### 4.1 공통 기록 저장 서비스

`src/offline-entry-repository.js`를 새로 만들고 수동 입력과 타이머가 모두 이 API를 사용한다.

주요 함수:

```js
saveEntryLocalFirst({ userId, entry, clearActiveTimer })
flushPendingEntries({ userId })
listPendingEntries(userId)
mergeRemoteAndPendingEntries(remoteEntries, pendingEntries)
```

`saveEntryLocalFirst` 흐름:

1. `crypto.randomUUID()` 또는 동등한 방식으로 `localId`를 만든다.
2. Firestore 문서 ID도 같은 `localId`를 사용한다.
3. 기록을 먼저 `pendingEntries`에 저장한다.
4. 앱 상태에 즉시 추가해 대시보드와 기록 내역을 다시 그린다.
5. 온라인으로 판단되면 즉시 동기화를 시도한다.
6. 서버 쓰기가 성공하면 대기함에서 제거하고 `synced` 결과를 반환한다.
7. 네트워크 오류이면 대기함에 유지하고 `queued` 결과를 반환한다.
8. 권한 오류, 잘못된 데이터처럼 재시도해도 해결되지 않는 오류는 `failed`로 표시하고 사용자가 알 수 있게 한다.

네트워크 연결 여부는 `navigator.onLine`만으로 성공을 단정하지 않는다. 실제 Firestore 쓰기 결과를 기준으로 최종 상태를 정한다.

### 4.2 중복 방지

Firestore 기록 문서는 자동 생성 ID 대신 `localId`를 문서 ID로 사용한다.

```text
users/{uid}/entries/{localId}
```

동기화는 `setDoc(..., { merge: true })`로 수행한다. 같은 항목을 여러 번 재시도해도 하나의 문서만 존재한다.

### 4.3 수동 입력

`기록 저장`을 누르면 버튼을 잠시 비활성화하고 공통 저장 서비스를 호출한다.

성공 상태:

- 서버 저장 성공: 입력 폼을 초기화하되 마지막 선택 대분류와 수동 입력 방식은 유지한다.
- 오프라인 대기: 같은 방식으로 폼을 초기화하고 기록 내역에 `동기화 대기` 항목을 즉시 보여준다.
- IndexedDB 저장 실패: 폼을 초기화하지 않고 오류를 표시한다.

### 4.4 타이머

타이머 시작 상태는 기존처럼 기기 로컬 저장소에 즉시 저장한다. 온라인일 때만 Firestore의 `activeTimer/current` 동기화를 시도한다. 오프라인 시작은 로컬 타이머만으로 계속 사용할 수 있다.

타이머 종료 시 완성된 기록을 공통 저장 서비스에 넣는다.

- 온라인 종료: 기록 문서 저장과 `activeTimer/current` 삭제를 같은 배치로 처리한다.
- 오프라인 종료: 완성 기록을 대기함에 저장하고 로컬 타이머는 종료한다. 대기 항목에 `clearActiveTimer: true`를 저장해 다음 동기화 때 기록 저장과 원격 활성 타이머 삭제를 함께 수행한다.
- 동일 시작 시각에서 만든 기록 ID를 재사용해 중복 종료 저장을 막는다.

다른 기기와 오프라인 타이머가 동시에 실행되는 극단적 충돌에서는 이미 서버에 존재하는 활성 타이머를 덮어쓰지 않는다. 완성 기록은 고유 ID로 저장하고, 원격 활성 타이머 삭제는 해당 타이머의 시작 시각과 사용자 ID가 일치할 때만 수행한다.

## 5. 자동 동기화

`src/offline-sync.js`가 사용자별 동기화를 한 번에 하나만 실행한다.

동기화 시작 조건:

- 인증된 사용자의 앱 시작
- 기록을 대기함에 저장한 직후
- `window`의 `online` 이벤트
- `visibilitychange`에서 앱이 다시 보이게 될 때
- 메뉴 이동이나 데이터 새로고침 중 정상 네트워크 요청이 성공했을 때

처리 규칙:

- 생성 순서대로 한 항목씩 처리한다.
- 하나의 항목 실패가 다음 항목의 영구 중단으로 이어지지 않도록 오류 유형을 구분한다.
- 일시적 네트워크 오류는 대기 상태로 남긴다.
- 인증 만료나 권한 오류는 자동 반복하지 않고 오류 상태로 남겨 로그인 갱신 후 다시 시도한다.
- 성공한 항목은 대기함에서 제거하고 앱 상태의 같은 `localId`를 서버 저장 상태로 바꾼다.
- 동기화 완료 후 대시보드, 기록 내역, 통계 데이터 갱신 이벤트를 보낸다.

## 6. 사용자 데이터 스냅숏

오프라인에서 대분류를 선택하려면 마지막 온라인 데이터가 필요하다. Firestore 조회가 성공할 때마다 `userSnapshots`에 다음 값을 저장한다.

- 활성 대분류와 순서
- 보관 대분류 이름
- 최근 기록
- 주간·일간 예산
- 기본 요일 비율

앱 시작 시 순서:

1. Firebase 인증의 로컬 지속 상태에서 사용자를 확인한다.
2. 해당 사용자의 IndexedDB 스냅숏을 먼저 읽어 화면을 그린다.
3. 네트워크 조회를 시도한다.
4. 성공하면 최신 데이터로 교체하고 스냅숏을 갱신한다.
5. 실패하면 캐시 화면을 유지하고 오프라인 상태를 조용히 안내한다.

대분류 스냅숏이 전혀 없는 첫 오프라인 실행에서는 기록 폼을 사용할 수 없으며, `온라인에서 한 번 실행한 뒤 사용할 수 있습니다`라고 안내한다.

## 7. 저장 결과 알림 배너

`src/app-toast.js`에서 모든 저장·동기화 알림을 처리한다. 화면 아래 안전 영역 위에 표시하며, 모바일 홈 화면 모드에서도 가려지지 않도록 `env(safe-area-inset-bottom)`을 반영한다.

메시지:

### 서버 저장 성공

```text
✓ 기록을 서버에 저장했습니다.
```

### 오프라인 대기

```text
✓ 기기에 안전하게 저장했습니다.
인터넷 연결 시 자동으로 반영됩니다. · 동기화 대기 N건
```

### 자동 동기화 완료

```text
✓ 대기 중이던 기록 N건을 서버에 반영했습니다.
```

### 기기 저장 실패

```text
기기에 기록을 저장하지 못했습니다. 입력 내용을 유지했습니다.
저장 공간과 브라우저 상태를 확인하세요.
```

배너는 기본 4초 후 사라진다. 오류 배너는 7초간 표시한다. 같은 종류의 알림이 연속되면 새 배너 하나로 교체한다.

기록 내역에서 대기 중 항목에는 `동기화 대기` 배지를 붙인다. 동기화 오류 항목에는 `동기화 실패` 배지와 다시 시도 버튼을 표시한다.

## 8. 마지막 화면과 내부 상태 복원

`src/ui-session-state.js`가 사용자별 화면 상태를 저장한다.

저장 구조:

```js
{
  activeView: 'dashboard',
  dashboard: {
    mode: 'daily',
    selectedDate: '2026-07-27',
    selectedWeekStart: '2026-07-27',
    calendarYear: 2026,
    calendarMonth: 7
  },
  record: {
    tab: 'manual',
    manualMode: 'duration'
  },
  budget: {
    mode: 'week'
  },
  statistics: {
    mode: 'monthly-comparison',
    weekStart: '2026-07-27',
    year: 2026,
    month: 7
  }
}
```

복원 규칙:

- 인증된 사용자의 데이터만 복원한다.
- 저장된 메뉴가 존재하지 않거나 현재 화면에서 지원되지 않으면 대시보드로 돌아간다.
- 미래 날짜·미래 주처럼 기존 제한을 위반하는 값은 오늘 또는 이번 주로 보정한다.
- 삭제된 대분류 ID와 같은 화면 외 데이터는 저장하지 않는다.
- 진행 중 타이머가 있어도 마지막 사이드 메뉴는 그대로 복원한다.
- 마지막 메뉴가 `시간 기록`인 경우에만 진행 중 타이머가 있으면 내부 탭을 `타이머`로 복원한다. 다른 메뉴에서는 메뉴 또는 상단의 실행 중 표시로 타이머 상태를 알린다.

각 기능 모듈은 내부 상태가 바뀔 때 `ui-session-state`에 저장하고, 초기 렌더링 전에 복원값을 주입받는다. DOM이 그려진 뒤 억지로 클릭을 재현하는 방식은 사용하지 않는다.

## 9. 온라인·오프라인 상태 표시

상시 큰 배너는 두지 않는다. 다음 상황에서만 짧게 알린다.

- 앱이 캐시 데이터로 열렸고 서버 갱신에 실패한 경우: `오프라인 상태입니다. 새 기록은 기기에 저장됩니다.`
- 인터넷이 돌아오고 동기화가 완료된 경우: 완료 배너
- 대기 기록이 존재하는 동안 기록 내역 항목에 상태 배지 표시

`navigator.onLine`은 안내 보조 정보로만 사용하며 저장 성공 판정에는 사용하지 않는다.

## 10. 데이터 삭제와 로그아웃

- 대분류 완전 삭제는 서버 기록뿐 아니라 같은 사용자의 오프라인 대기함에서 해당 대분류에 연결된 기록도 찾아 경고한다.
- 이미 완성된 오프라인 기록이 있으면 대분류 삭제 시 함께 완전 삭제한다.
- 보관은 대기 기록의 이름 확인을 위해 보관 대분류 스냅숏을 유지한다.
- 로그아웃은 화면과 메모리의 사용자 데이터를 비우지만 IndexedDB 대기함은 유지한다.
- 다른 계정이 로그인하면 이전 계정의 대기 기록·스냅숏·화면 상태를 읽지 않는다.

## 12. 테스트 계획

### 단위 테스트

- IndexedDB 대기 항목 추가·조회·삭제
- 사용자 ID별 데이터 격리
- 동일 `localId` 재시도 중복 방지
- 원격 성공 시 대기 항목 제거
- 네트워크 오류 시 대기 상태 유지
- 영구 오류 상태 분류
- 원격 기록과 대기 기록 병합 시 중복 제거
- UI 상태 직렬화·복원과 미래 기간 보정

### 통합 테스트

- 수동 기록 온라인 저장 후 성공 배너
- 수동 기록 오프라인 저장 후 대기 배너와 즉시 목록 반영
- 타이머 종료 오프라인 저장 후 앱 재실행에서도 기록 유지
- 온라인 이벤트 후 자동 동기화와 완료 배너
- 동기화 재시도에도 Firestore 문서가 하나만 생성됨
- 로그아웃 후 다른 사용자가 이전 사용자의 대기 기록을 볼 수 없음
- 마지막 메뉴와 내부 탭 복원
- 진행 중 타이머와 마지막 메뉴가 함께 안전하게 복원됨
- 서비스 워커 앱 셸 캐시와 오프라인 재실행
- 기존 기록·통계·예산·대분류 삭제 회귀 테스트

### 수동 검증

- iPhone 홈 화면 웹앱에서 비행기 모드 저장
- 앱 강제 종료 후 오프라인 재실행
- 여러 건 기록 후 인터넷 연결 복구
- 불안정한 네트워크에서 버튼 연속 입력
- 저장 배너가 하단 안전 영역과 겹치지 않는지 확인

## 13. 성공 기준

- `기록 저장` 또는 `종료하고 저장`을 한 번 누르면 IndexedDB 저장이 먼저 성공하고, 서버 연결이 가능하면 이어서 Firestore에도 반영된다.
- IndexedDB 저장 실패가 아닌 한 사용자는 즉시 서버 저장 또는 동기화 대기 상태를 확인한다.
- 오프라인 기록은 앱 종료 후에도 남고, 같은 사용자가 다시 로그인하면 보인다.
- 인터넷이 돌아오면 사용자 조작 없이 자동으로 서버에 반영된다.
- 같은 기록이 중복 생성되지 않는다.
- 마지막 메뉴와 내부 탭·기간이 앱 재실행 후 복원된다.
- 기존 온라인 기능과 통계 계산은 바뀌지 않는다.
