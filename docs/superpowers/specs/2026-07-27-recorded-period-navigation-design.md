# 기록 기간 중심 대시보드·통계 이동 설계

## 1. 목적

대시보드와 통계의 기간 이동 방식을 일관되게 정리한다. 과거 기간은 실제 시간 기록이 존재할 때만 이동 대상으로 삼고, 현재 기간인 오늘·이번 주·이번 달은 기록이 없어도 항상 조회할 수 있게 한다.

핵심 원칙은 다음과 같다.

> 과거는 실제 기록이 있는 기간만 이동하고, 오늘·이번 주·이번 달은 기록이 없어도 항상 표시한다.

예산만 존재하고 실제 기록이 없는 과거 날짜·주·월은 이동 대상에 포함하지 않는다. 서버에 아직 동기화되지 않은 기기 대기 기록도 실제 기록으로 간주한다.

## 2. 공통 기록 기간 인덱스

수동 기록, 타이머 기록, Firestore 기록, IndexedDB 동기화 대기·실패 기록을 하나로 병합한 최종 기록 목록을 기준으로 다음 인덱스를 생성한다.

기록 기간으로 인정하는 항목은 유효한 `YYYY-MM-DD` 날짜와 `0분보다 큰 durationMinutes`를 가진 기록이다. 삭제 표시된 항목, 유효하지 않은 날짜, 0분 또는 음수 기록은 기간 인덱스에서 제외한다.

- `recordedDates`: 실제 기록이 존재하는 날짜 목록
- `recordedWeekStarts`: 실제 기록이 존재하는 주의 월요일 목록
- `recordedMonths`: 실제 기록이 존재하는 `YYYY-MM` 목록
- `recordedYears`: 실제 기록이 존재하는 연도 목록

현재 기간은 별도로 항상 허용한다.

- 일간 이동 대상: `recordedDates + 오늘`
- 주간 이동 대상: `recordedWeekStarts + 이번 주`
- 월간 선택 대상: `recordedMonths + 이번 달`

중복은 제거하고 오름차순으로 정렬한다. 미래 기간은 포함하지 않는다.

공통 순수 함수는 다음 책임을 가진다.

- 기록 목록에서 날짜·주·월 인덱스 생성
- 현재 선택 기간보다 가까운 이전 기록 기간 찾기
- 현재 선택 기간보다 가까운 이후 기록 기간 찾기
- 이후 기록 기간이 없을 때 현재 기간으로 이동할지 결정
- 삭제 후 현재 선택 기간이 무효가 되었을 때 가장 가까운 유효 기간으로 보정

이 공통 로직을 대시보드 일간·주간과 통계 주별·월간이 함께 사용한다.

## 3. 대시보드 일간

기존 동작을 유지하되 현재 날짜도 활성 기간으로 명시한다.

### 초기 표시

- 앱을 열면 기록 유무와 관계없이 오늘을 표시한다.
- 복원된 선택 날짜가 미래이면 오늘로 보정한다.
- 복원된 과거 선택 날짜에 기록이 없으면 가장 가까운 유효 날짜로 보정한다. 이전 기록 날짜를 우선하고, 없으면 이후 기록 날짜, 그것도 없으면 오늘을 사용한다.

### 전날·다음날

- `전날`: 가장 가까운 이전 기록 날짜로 이동한다.
- 이전 기록 날짜가 없으면 비활성화한다.
- `다음날`: 가장 가까운 이후 기록 날짜로 이동한다.
- 이후 기록 날짜가 없고 현재 선택 날짜가 오늘보다 과거이면 오늘로 이동한다.
- 오늘에서는 `다음날`을 비활성화한다.

### 달력

- 기록이 있는 날짜와 오늘만 활성화한다.
- 기록이 없는 과거 날짜와 모든 미래 날짜는 비활성화한다.
- 오늘은 기록이 없어도 선택 가능하다.

## 4. 대시보드 주간

### 초기 표시

- 주간 탭을 처음 열면 기록 유무와 관계없이 이번 주를 표시한다.
- 복원된 과거 주가 기록 없는 주라면 가장 가까운 유효 주로 보정한다.
- 보정 순서는 이전 기록 주, 이후 기록 주, 이번 주이다.
- 미래 주는 항상 이번 주로 보정한다.

### 전주 버튼

- 바로 7일 전으로 이동하지 않는다.
- 가장 가까운 이전 기록 주로 이동한다.
- 이전 기록 주가 없으면 비활성화한다.
- 이번 주에 기록이 없어도 과거 기록 주가 있으면 `전주`는 활성화한다.

### 다음 주 버튼

과거 기록 주를 보고 있을 때 다음 순서로 이동한다.

1. 가장 가까운 이후 기록 주
2. 이후 기록 주가 없으면 이번 주

이번 주에서는 `다음 주`를 비활성화한다.

### 예시

기록 주가 `7월 6일 주`, `7월 20일 주`이고 이번 주가 `7월 27일 주`라면 다음과 같이 동작한다.

- `7월 6일 주 → 다음 주 → 7월 20일 주`
- `7월 20일 주 → 다음 주 → 이번 주`
- `이번 주 → 전주 → 7월 20일 주`
- `이번 주 → 다음 주`는 비활성화

기록 주가 하나도 없어도 이번 주는 표시하며 전주·다음 주는 모두 비활성화한다.

## 5. 통계 주별 통계

주별 통계는 대시보드 주간과 동일한 기록 주 인덱스와 이동 규칙을 사용한다.

### 초기 표시

- 주별 통계 진입 시 이번 주를 표시한다.
- 이번 주에 기록이 없어도 빈 통계를 정상 표시한다.
- 저장된 과거 주가 기록 없는 주이면 가장 가까운 유효 주로 보정한다.

### 이전 주·다음 주

- `이전 주`: 가장 가까운 이전 기록 주로 이동한다.
- 이전 기록 주가 없으면 비활성화한다.
- `다음 주`: 가장 가까운 이후 기록 주로 이동한다.
- 이후 기록 주가 없으면 이번 주로 이동한다.
- 이번 주에서는 비활성화한다.
- 기록이 없는 중간 주는 모두 건너뛴다.

### 이번 주에 기록이 없는 경우

통계 화면은 유지하며 다음 정보를 표시한다.

- 기간 예산: 이번 주에 적용되는 예산
- 실제 기록: `0분`
- 기록 일수: `0일`
- 예산이 있으면 달성률 `0%`
- 예산과 기록이 모두 없으면 달성률 `—`

## 6. 통계 월간 통계

### 초기 표시

- 월간 통계 진입 시 기록 유무와 관계없이 이번 달을 표시한다.
- 이번 달에 기록이 없어도 다른 과거 월로 자동 이동하지 않는다.
- 복원된 과거 월에 기록이 없다면 같은 연도의 가장 가까운 기록 월로 보정한다.
- 거리가 같은 기록 월이 양쪽에 있으면 이전 월을 우선한다.
- 같은 연도에 기록 월이 없으면 현재 연도·이번 달로 이동한다.

### 월 선택 목록

모든 1월부터 12월까지 표시하되 활성 상태를 구분한다.

활성화 대상:

- 이번 달
- 실제 기록이 있는 과거 월

비활성화 대상:

- 기록이 없는 과거 월
- 모든 미래 월

비활성 월은 흐리게 표시하고 선택할 수 없게 한다.

### 연도 선택 목록

- 현재 연도는 기록이 없어도 항상 표시한다.
- 과거 연도는 실제 기록이 있는 연도만 표시한다.
- 현재 연도를 선택하면 이번 달을 기본 선택한다.
- 과거 연도를 선택하면 그 연도의 가장 최근 기록 월을 기본 선택한다.
- 선택한 과거 연도에 기록 월이 없다면 해당 연도는 목록에 나타나지 않는다.

### 이번 달에 기록이 없는 경우

월간 통계 화면은 유지하며 다음 정보를 표시한다.

- 실제 기록: `0분`
- 기록 일수: `0일`
- 기록이 있는 주가 없으므로 기존 월간 예산 계산 원칙에 따라 기간 예산 `0분`
- 기간 예산과 실제 기록이 모두 0이면 달성률 `—`

## 7. 기록 변경 후 기간 보정

기록 저장, 삭제, 동기화 완료, 대분류 완전 삭제 후 공통 기록 기간 인덱스를 다시 계산한다.

### 현재 기간

오늘·이번 주·이번 달은 기록이 모두 없어져도 그대로 유지한다.

### 과거 기간

현재 보고 있는 과거 날짜·주·월의 마지막 기록이 삭제되어 해당 기간이 무효가 되면 다음 순서로 이동한다.

1. 가장 가까운 이전 기록 기간
2. 이전 기간이 없으면 가장 가까운 이후 기록 기간
3. 이후 기간도 없으면 현재 기간

화면 상태 저장소에도 보정된 기간을 다시 저장해 앱을 재실행했을 때 무효한 기간으로 복원되지 않게 한다.

## 8. 오프라인 기록 포함

기간 인덱스는 서버 기록만 사용하지 않는다. IndexedDB에 저장된 동기화 대기 기록과 동기화 실패 기록도 실제 기록으로 포함한다.

따라서 오프라인 상태에서 기록한 직후에도 다음이 즉시 갱신된다.

- 대시보드 달력의 활성 날짜
- 대시보드 주간의 전주·다음 주 이동 대상
- 통계 주별 이전 주·다음 주 이동 대상
- 통계 월간의 활성 월

동기화 완료 후에도 동일한 기록 ID를 사용하므로 기간 인덱스가 중복되지 않는다.

## 9. 버튼 및 접근성

이동 대상이 없을 때 버튼을 숨기지 않고 비활성화한다.

- 실제 `disabled` 속성 사용
- `aria-disabled` 상태 일치
- 비활성 스타일은 기존 보조 버튼 스타일을 재사용
- 비활성 버튼은 클릭·키보드 실행 모두 차단

월 선택의 비활성 옵션도 실제 `disabled` 속성을 사용한다.

## 10. 구현 경계

### 공통 도메인

새 파일 `src/recorded-period-domain.js`에 다음 순수 로직을 둔다.

- 기록 날짜·주·월·연도 인덱스 생성
- 이전·다음 기록 기간 탐색
- 현재 기간을 포함한 이동 대상 생성
- 복원·삭제 후 선택 기간 보정

이 파일은 DOM, Firebase, IndexedDB에 직접 의존하지 않고 기록 배열과 현재 날짜만 입력받는다.

### 대시보드

`time-budget-feature.js`에서 서버·오프라인 기록이 병합된 `state.entries`로 공통 인덱스를 계산해 `time-budget-ui.js`에 이전·다음 목적지와 버튼 활성 상태를 전달한다.

### 통계

`statistics-offline-rescue.js`에서 서버 기록과 오프라인 기록이 병합된 `state.data.entries`를 기준으로 동일한 인덱스를 계산한다. 주별 이동과 월 선택 비활성화에 사용한다.

### 화면 상태 복원

`statistics-session-state.js`는 저장된 기간을 직접 강제로 이동시키기 전에 통계 로더가 계산한 유효 기간으로 보정된 상태를 따른다. 무효한 과거 주·월을 반복 복원하지 않는다.

## 11. 테스트

### 순수 함수 테스트

- 날짜가 여러 주에 흩어졌을 때 주 시작일 목록 생성
- 같은 주의 여러 기록은 하나의 주로 합침
- 기록 월·연도 목록 생성
- 0분·음수·무효 날짜 기록 제외
- 이전·다음 기록 주 탐색
- 이후 기록 주가 없을 때 이번 주 반환
- 오늘·이번 주·이번 달 항상 포함
- 미래 기간 제외
- 오프라인 대기·실패 기록 포함

### 대시보드 테스트

- 주간 진입 시 이번 주 표시
- 전주가 가장 가까운 기록 주로 이동
- 기록 없는 중간 주 건너뜀
- 이전 기록 주가 없으면 전주 비활성화
- 과거 기록 주에서 다음 주가 이후 기록 주 또는 이번 주로 이동
- 이번 주에서 다음 주 비활성화

### 통계 테스트

- 주별 통계가 대시보드와 같은 주 목록 사용
- 이전·다음 주 버튼 상태와 이동 목적지 검증
- 이번 주 무기록 상태에서도 통계 표시
- 월간 통계 진입 시 이번 달 표시
- 기록 없는 과거 월과 미래 월 비활성화
- 이번 달은 무기록이어도 활성화
- 과거 연도 선택 시 가장 최근 기록 월 선택
- 무효한 저장 상태는 이전 기록 월을 우선해 보정

### 회귀 테스트

- 통계 탭 이후 다른 메뉴 이동 가능
- 통계 캐시 우선 로딩과 8초 제한 유지
- 서비스 워커 배포 산출물에 변경 파일 포함
- 모바일에서 기간 버튼과 월 선택이 가로 넘침 없이 표시

## 12. 완료 기준

다음 조건을 모두 충족하면 구현 완료로 본다.

- 대시보드 주간이 기록 없는 과거 주를 건너뛴다.
- 통계 주별 이동도 동일하게 동작한다.
- 대시보드와 통계에서 이동 불가능한 방향 버튼이 비활성화된다.
- 월간 통계에서 기록 없는 과거 월과 미래 월이 비활성화된다.
- 오늘·이번 주·이번 달은 기록이 없어도 항상 표시된다.
- 오프라인 대기·실패 기록이 모든 기간 인덱스에 즉시 포함된다.
- 기록 삭제 후 무효한 과거 기간이 자동 보정된다.
- 기존 통계 로딩, 메뉴 이동, 모바일 반응형, 오프라인 기능의 회귀 테스트가 모두 통과한다.
