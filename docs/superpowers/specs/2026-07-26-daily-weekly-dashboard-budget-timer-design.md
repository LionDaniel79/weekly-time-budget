# 일간·주간 대시보드, 시간 예산, 복구형 타이머 설계

## 1. 목적

기존 주간 중심 화면을 다음 세 가지 방향으로 확장한다.

1. 대시보드에서 기록이 있는 날짜의 일간 현황과 과거 주간 현황을 조회한다.
2. 기존 `이번 주 예산` 메뉴를 `시간 예산`으로 바꾸고, `오늘`과 `이번 주` 예산을 분리해서 설정한다.
3. 아이폰이나 브라우저가 백그라운드로 전환되거나 페이지가 다시 로드되어도 진행 중인 타이머를 복구한다.

## 2. 확정된 메뉴 구조

사이드 메뉴 순서는 다음과 같다.

1. 대시보드
2. 시간 기록
3. 시간 예산
4. 기록 내역
5. 통계
6. 대분류 관리

기존 `이번 주 예산` 메뉴명과 페이지 제목은 모두 `시간 예산`으로 변경한다.

## 3. 대시보드

대시보드 상단에는 두 개의 탭을 둔다.

- `일간`
- `주간`

첫 진입 시 기본 탭은 `일간`, 기본 날짜는 오늘이다.

### 3.1 일간 탭

#### 기간 이동

- `전날` 버튼은 단순히 하루 전으로 이동하지 않는다.
- 현재 선택 날짜보다 이전에 실제 기록이 존재하는 날짜 중 가장 가까운 날짜로 이동한다.
- `다음날` 버튼은 현재 선택 날짜보다 이후에 실제 기록이 존재하는 날짜 중 가장 가까운 날짜로 이동한다.
- 이후 기록 날짜가 없고 현재가 과거 날짜라면 오늘로 이동한다.
- 오늘에서는 `다음날` 버튼을 비활성화한다.
- 미래 날짜는 조회하지 않는다.

#### 달력

- 일반 날짜 입력기가 아니라 기록 날짜만 선택 가능한 사용자 정의 달력을 사용한다.
- 실제 기록이 한 건 이상 있는 날짜만 활성화한다.
- 기록이 없는 날짜와 미래 날짜는 비활성화한다.
- 오늘은 기록이 없어도 현재 상태 확인을 위해 별도 `오늘` 버튼으로 접근할 수 있다.

#### 표시 내용

선택한 날짜에 대해 다음을 표시한다.

- 전체 적용 예산
- 전체 실제 기록
- 전체 달성률
- 대분류별 실제 기록 / 적용 예산 / 달성률
- 예산 출처 표시
  - `직접 설정`
  - `요일 비율 적용`

기록이 없는 오늘은 실제 기록 0분으로 표시한다. 과거 날짜는 기록이 있는 날짜만 조회 가능하다.

### 3.2 주간 탭

- `전주` 버튼으로 과거 주를 조회한다.
- `다음 주` 버튼은 과거 주에서만 활성화한다.
- 이번 주에서는 `다음 주` 버튼을 비활성화한다.
- 미래 주는 조회하지 않는다.
- 현재 주간 대시보드의 전체 달성률, 전체 예산, 실제 기록, 대분류별 달성률 구조를 유지한다.
- 과거 주는 그 주에 저장된 주간 예산과 요일 배분 비율 스냅숏을 사용한다.

## 4. 시간 예산 화면

상단에 두 개의 탭을 둔다.

- `오늘`
- `이번 주`

화면 폭 선택 버튼은 두지 않는다. CSS 미디어 쿼리와 유동형 그리드를 이용해 데스크톱, 태블릿, 모바일에 자동 적응한다.

### 4.1 오늘 탭

실제 오늘 날짜의 대분류별 예산만 설정한다. 과거 또는 미래 날짜는 이 화면에서 편집하지 않는다.

모든 활성 대분류를 표시하되, 사용자가 필요한 대분류만 직접 입력할 수 있다.

입력값 의미는 다음과 같다.

- 빈칸: `이번 주 예산 × 오늘 요일 비율`로 자동 계산
- `0`: 오늘 해당 대분류 예산을 명시적으로 0분으로 설정
- 양수: 오늘 직접 설정한 예산

각 입력칸에는 현재 자동 계산값을 보조 문구로 표시한다.

예:

- 논문: 자동 2시간
- 독서: 직접 1시간
- 기도: 직접 0시간

오늘 직접 설정한 값은 같은 주 안에서 주간 예산이나 요일 비율이 바뀌어도 유지한다. 입력값을 지우고 저장하면 해당 대분류만 자동 계산 방식으로 복귀한다.

화면 맨 아래에는 `저장` 버튼 하나만 둔다.

### 4.2 이번 주 탭

한 화면 안에 다음 두 구역을 배치한다.

#### 대분류별 이번 주 총예산

입력값 의미는 다음과 같다.

- 빈칸: 대분류 관리에 저장된 기본 주간 예산 사용
- `0`: 이번 주 해당 대분류 예산을 명시적으로 0분으로 설정
- 양수: 이번 주에만 적용할 주간 예산

#### 요일별 공통 배분 비율

- 월요일부터 일요일까지 7개 입력칸을 제공한다.
- 이 비율은 모든 대분류에 공통으로 적용한다.
- 입력값은 꼭 백분율 합계 100일 필요가 없다.
- 입력값의 상대 비율을 자동으로 100%로 환산한다.
- 모든 값이 비어 있거나 합계가 0이면 7일 균등 배분을 적용한다.
- 환산된 실제 백분율을 입력란 아래에 즉시 표시한다.

예:

`2, 2, 1, 1, 1, 2, 1` 입력 시

`20%, 20%, 10%, 10%, 10%, 20%, 10%`로 저장한다.

화면 맨 아래에는 `저장` 버튼 하나만 둔다.

## 5. 예산 적용 우선순위

특정 날짜와 대분류의 적용 예산은 다음 우선순위로 결정한다.

1. 그 날짜에 직접 저장한 일간 예산
2. 그 주의 주간 예산 × 그 주에 저장된 요일 비율
3. 그 주의 주간 예산이 비어 있으면 대분류 기본 주간 예산 × 요일 비율
4. 요일 비율이 한 번도 설정되지 않았으면 7일 균등 배분

직접 일간 예산의 `0`은 유효한 명시적 값이다. 빈칸만 자동 계산을 의미한다.

## 6. 주간 비율 이월과 과거 보존

- 요일별 비율은 한 번 저장하면 기본 비율로 유지한다.
- 다음 주가 시작되면 가장 최근 기본 비율이 자동 적용된다.
- 사용자가 비율을 바꾸면 변경한 주부터 이후 주에 적용한다.
- 과거 주는 당시 저장된 비율 스냅숏을 유지한다.
- 오늘 직접 설정한 일간 예산은 다음 주로 이월하지 않는다.
- 다음 주의 일간 예산은 새 주간 예산과 유지된 요일 비율을 기준으로 새로 계산한다.

## 7. 데이터 모델

### 7.1 주간 예산 문서

컬렉션:

`users/{uid}/weeklyBudgets/{weekStart}`

필드:

- `weekStart`
- `budgets`: 대분류별 주간 예산 분
- `dayWeights`: 월~일 정규화된 비율
- `updatedAt`

과거 주의 재현을 위해 각 주 문서에 그 주에 적용된 `dayWeights`를 함께 저장한다.

### 7.2 기본 요일 비율 문서

문서:

`users/{uid}/settings/timeBudget`

필드:

- `defaultDayWeights`
- `updatedAt`

새 주를 처음 열 때 해당 기본 비율을 주간 예산 문서의 스냅숏으로 복사한다.

### 7.3 일간 직접 예산 문서

컬렉션:

`users/{uid}/dailyBudgets/{date}`

필드:

- `date`
- `overrides`: 직접 설정한 대분류만 포함
- `updatedAt`

`overrides`에 키가 없으면 자동 계산을 사용한다. 값 `0`은 명시적 0분이다.

## 8. 반올림 규칙

주간 예산을 요일 비율로 분배할 때 각 날짜는 분 단위 정수로 계산한다.

- 월~토는 일반 반올림한다.
- 마지막 요일은 주간 총합과 정확히 일치하도록 남은 분을 배정한다.
- 직접 설정한 일간 예산은 이 자동 분배 합계 보정 대상에서 제외하지 않는다. 대시보드에서는 직접 설정값을 우선 표시하며, 주간 총예산 자체는 별도로 유지한다.

## 9. 복구형 타이머

### 9.1 플랫폼 제약

iOS와 일반 브라우저는 백그라운드 웹페이지의 자바스크립트 실행을 제한하거나 완전히 중지할 수 있다. 따라서 1초 간격 코드를 백그라운드에서 계속 실행시키는 방식으로는 안정성을 보장할 수 없다.

### 9.2 설계 원칙

타이머는 `계속 실행`이 아니라 `시작 상태를 저장하고 현재 시각으로 복원`하는 방식으로 구현한다.

타이머 시작 시 다음 정보를 저장한다.

- 대분류 ID
- 메모
- 시작 시각의 절대 타임스탬프
- 시작 날짜
- 실행 중 상태
- 사용자 ID

저장 위치:

1. Firestore의 `users/{uid}/activeTimer/current`
2. 동일 기기의 `localStorage`

Firestore가 주 저장소이며 localStorage는 네트워크 지연과 초기 화면 복구를 위한 보조 저장소다.

### 9.3 복구 동작

- 앱을 다시 열거나 로그인 상태가 복구되면 진행 중 타이머를 조회한다.
- 경과 시간은 `현재 시각 - 시작 시각`으로 계산한다.
- `setInterval`은 화면 표시 갱신에만 사용한다.
- 페이지 숨김/복귀 시 `visibilitychange` 이벤트로 즉시 다시 계산한다.
- 앱 재시작, 화면 잠금, 백그라운드 전환 후에도 종료 버튼을 누르면 전체 실제 경과 시간을 저장한다.
- 타이머 종료 저장이 성공한 뒤에만 activeTimer 문서와 localStorage를 삭제한다.
- 저장 실패 시 진행 중 타이머 상태를 유지하고 재시도 안내를 표시한다.
- 사용자가 취소하면 확인 후 activeTimer 상태만 삭제하고 기록은 만들지 않는다.

## 10. 구성 요소 분리

기존 `app.js`에 모든 규칙을 추가하지 않고 다음 단위로 분리한다.

- `src/time-budget-domain.js`
  - 비율 정규화
  - 자동 일간 예산 계산
  - 직접 예산 우선순위
  - 기록 날짜 탐색
- `src/time-budget-ui.js`
  - 대시보드 일간/주간 탭
  - 시간 예산 오늘/이번 주 탭
  - 사용자 정의 기록 날짜 달력
- `src/persistent-timer.js`
  - 타이머 시작 상태 생성
  - localStorage 저장·복구
  - Firestore activeTimer 직렬화
  - 경과 시간 계산
- 기존 `app.js`
  - Firebase 초기화와 기존 화면 진입점 유지
  - 새 모듈과의 연결만 담당

## 11. 반응형 화면

별도의 `넓은 화면`, `모바일 화면` 선택 버튼은 만들지 않는다.

- 넓은 화면: 대분류 이름, 자동값, 입력칸을 같은 행에 배치
- 좁은 화면: 각 대분류를 카드 형태로 세로 배치
- 요일 비율 입력: 넓은 화면에서는 7열, 모바일에서는 2~3열로 자동 줄바꿈
- 버튼과 입력칸은 최소 44px 터치 영역 확보
- 가로 스크롤이 생기지 않도록 모든 그리드에 `minmax(0, 1fr)`과 `max-width: 100%` 적용

## 12. 오류 처리

- 음수 예산은 저장하지 않는다.
- 소수 시간은 기존 입력 정책에 맞춰 0.5시간 단위를 허용하거나 분 단위 정수로 변환한다.
- 비율 입력에 음수가 있으면 저장하지 않는다.
- 주간 문서가 없으면 기본 주간 예산과 기본 요일 비율로 화면을 구성한다.
- 일간 직접 예산 문서가 없으면 자동 예산만 사용한다.
- 기록 날짜가 하나도 없으면 일간 대시보드는 오늘만 표시하고 전날·달력 버튼을 비활성화한다.
- Firebase 읽기 실패 시 기존 화면을 지우지 않고 오류 안내와 재시도 버튼을 표시한다.

## 13. 테스트 기준

### 도메인 테스트

- 비율 합계가 100이 아니어도 정확히 정규화되는지
- 전부 빈 값 또는 0일 때 균등 배분되는지
- 주간 총분과 일간 자동 예산 합계가 일치하는지
- 빈칸과 명시적 0이 구분되는지
- 오늘 직접 예산이 자동 예산보다 우선하는지
- 다음 주에는 오늘 직접 예산이 이월되지 않는지
- 과거 주가 당시 비율 스냅숏을 사용하는지
- 이전·다음 기록 날짜 탐색이 가장 가까운 날짜를 반환하는지

### UI 테스트

- 메뉴명이 `시간 예산`으로 표시되는지
- 대시보드에 `일간 / 주간` 탭이 있는지
- 시간 예산에 `오늘 / 이번 주` 탭이 있는지
- 두 화면 모두 저장 버튼 문구가 `저장`인지
- 기록이 있는 날짜만 달력에서 활성화되는지
- 오늘과 이번 주에서 미래 이동 버튼이 비활성화되는지
- 360px 화면에서 가로 스크롤이 생기지 않는지
- 화면 폭 선택 버튼이 존재하지 않는지

### 타이머 테스트

- 타이머 시작 상태가 localStorage와 Firestore용 데이터로 만들어지는지
- 페이지 재로딩 후 시작 시각을 기준으로 경과 시간이 복원되는지
- 백그라운드 시간 동안 setInterval이 멈춰도 경과 시간이 정확한지
- 종료 저장 성공 후에만 activeTimer가 제거되는지
- 종료 저장 실패 시 타이머 상태가 보존되는지
- 취소 시 기록을 만들지 않고 activeTimer만 제거되는지

## 14. 범위 제외

- iOS에서 웹앱 프로세스를 강제로 계속 실행시키는 기능

- 미래 주 대시보드 조회
- 모든 날짜의 일간 예산을 미리 생성하는 방식
