# 대분류 생성일 적용 설계

## 목적

새 대분류가 생성되기 전의 일간·주간·월간·연간 화면과 계산에 소급하여 나타나는 문제를 해결한다.

새 대분류는 **추가한 현지 날짜부터** 존재하는 것으로 처리한다. 추가일 이전에는 목록에 표시하지 않고, 예산 합계·개별 달성률·`목표 준수` 점수에서도 완전히 제외한다.

기존 대분류에는 생성일 정보가 없으므로 기존 통계와 사용 흐름을 보존하기 위해 시작일 제한이 없는 대분류로 처리한다.

---

## 확정 규칙

### 기존 대분류

- `createdDate`가 없는 대분류는 기존 대분류로 간주한다.
- 과거·오늘·미래의 모든 날짜에서 계속 활성 상태다.
- 업데이트 때문에 기존 대분류가 과거 통계에서 사라지거나 오늘 이후 비활성화되지 않는다.

### 새 대분류

- 대분류 추가 시 사용자의 현지 날짜를 `createdDate: YYYY-MM-DD` 형식으로 저장한다.
- `createdDate` 당일부터 활성 상태다.
- `createdDate` 이전 날짜에는 존재하지 않았던 항목처럼 처리한다.
- 성장 목표와 절제 목표 모두 동일한 시작일 규칙을 사용한다.

예:

```js
{
  name: '스마트폰',
  goalType: 'restraint',
  createdDate: '2026-07-29'
}
```

```text
2026-07-28: 비활성 — 표시·예산·점수·기록 선택에서 제외
2026-07-29: 활성 — 표시와 계산 시작
2026-07-30 이후: 계속 활성
```

## 데이터 모델

대분류 문서에 다음 필드를 추가한다.

```ts
type Category = {
  id: string;
  name: string;
  goalType?: 'growth' | 'restraint';
  createdDate?: string; // YYYY-MM-DD
  defaultBudgetMinutes?: number;
  order?: number;
};
```

### 호환성

- `createdDate` 없음: 모든 날짜에서 활성
- 유효한 `createdDate` 있음: 해당 날짜부터 활성
- 잘못된 형식의 `createdDate`: 기존 데이터 손상을 막기 위해 시작일 제한 없음으로 처리
- 기존 대분류를 일괄 마이그레이션하여 오늘 날짜를 넣지 않는다.

### 저장과 보존

- 새 대분류 생성 시에만 `createdDate`를 기록한다.
- 대분류 수정·순서 변경·일괄 저장에서는 `createdDate`를 변경하지 않는다.
- 보관할 때 원래 `createdDate`를 함께 저장한다.
- 복원할 때 원래 `createdDate`를 그대로 복원한다.
- 복원일을 새 생성일로 사용하지 않는다.

---

## 공통 활성 여부 함수

날짜별 활성 판단을 화면마다 중복 구현하지 않고 순수 함수로 통일한다.

```js
isCategoryActiveOnDate(category, dateKey)
```

규칙:

```text
createdDate가 없거나 유효하지 않음 → true
조회 날짜가 createdDate 이상         → true
조회 날짜가 createdDate 이전         → false
```

기간 안에서 대분류가 한 번이라도 활성인지 판단하는 함수도 둔다.

```js
isCategoryActiveInRange(category, startDate, endDate)
```

규칙:

```text
createdDate 없음                     → true
createdDate <= 기간 종료일           → true
createdDate > 기간 종료일            → false
```

기간 예산은 단순히 항목을 포함한 뒤 전체 예산을 넣지 않고, **기간 안의 각 날짜별 활성 여부를 적용하여 합산**한다.

---

## 일간 처리

선택한 날짜가 `createdDate` 이전이면 해당 대분류를 다음에서 제외한다.

- 일간 대시보드 대분류 목록
- 일간 예산 합계
- 실제 기록 합계의 대분류별 행
- 개별 달성률
- `목표 준수` 점수의 분자·분모
- 카운트다운 기준 예산
- 수동 입력 대분류 선택지

선택 날짜가 추가일과 같으면 정상적으로 포함한다.

---

## 주간 처리

주중에 대분류를 추가하면 추가일 이전 요일은 존재하지 않았던 날로 제외하고, 추가일부터 일요일까지만 일별 예산을 합산한다.

예: 목요일에 주간 기본 예산 7시간, 요일 비율이 모두 동일한 대분류 추가

```text
월 0시간 — 생성 전
화 0시간 — 생성 전
수 0시간 — 생성 전
목 1시간
금 1시간
토 1시간
일 1시간
주간 반영 예산: 4시간
```

중요한 원칙:

- 남은 4일에 주간 예산 7시간 전체를 재분배하지 않는다.
- 기존 요일별 배분 결과 중 활성 날짜의 몫만 반영한다.
- 주간 `목표 준수` 가중치도 4시간만 사용한다.
- 생성일이 해당 주의 일요일 이후라면 그 주에는 대분류 자체를 표시하지 않는다.

주간 예산 편집 화면은 현재 주에 이미 활성화된 대분류만 보여준다. 미래 시작일 기능은 없으므로 새 대분류는 생성 당일부터 현재 주 예산 편집에 나타난다.

---

## 월간·연간 처리

월간과 연간도 날짜별 활성 예산만 합산한다.

예: 7월 29일 생성

- 7월 1일~28일: 제외
- 7월 29일~31일: 포함
- 7월 월간 예산과 `목표 준수` 가중치는 29일 이후 몫만 반영
- 6월과 그 이전 월간 통계에는 대분류 행 자체가 나타나지 않음
- 해당 연도의 연간 통계에는 7월 29일 이후 기간만 반영
- 이후 연도에는 정상적으로 전체 기간 반영

기록이 있는 주·월만 보여주는 기존 통계 탐색 규칙은 유지한다. 생성일 때문에 기록이 없는 새 기간이 탐색 대상으로 새로 생기지는 않는다.

---

## 기록 입력과 검증

### 수동 입력

날짜를 먼저 선택하거나 변경하면 해당 날짜에 활성인 대분류만 선택 목록에 표시한다.

이미 선택한 대분류가 날짜 변경 후 비활성 상태가 되면 선택을 해제한다.

저장 시 UI 상태와 관계없이 다시 검증한다.

```text
선택 날짜 < 대분류 createdDate
→ 저장 차단
→ “이 대분류는 추가일 이전 날짜에 기록할 수 없습니다.” 표시
```

### 타이머

- 타이머 시작 목록에는 현재 날짜에 활성인 대분류만 표시한다.
- 타이머 시작 시 활성 여부를 다시 검사한다.
- 시작 당시 활성인 타이머는 자정을 지나 종료되어도 시작일 기준 기록으로 정상 저장한다.
- 기존 활성 타이머 복구 동작은 변경하지 않는다.

### 방어적 집계

정상 UI에서는 생성일 이전 기록을 만들 수 없지만, 오래된 클라이언트나 비정상 데이터로 그런 기록이 들어올 수 있다.

새 대분류의 `createdDate` 이전 기록은 대시보드·통계의 해당 대분류 집계에서 제외한다. 기록 내역에서도 표시하지 않는다. 이 방어 규칙은 `createdDate`가 있는 대분류에만 적용하며, 기존 대분류에는 영향을 주지 않는다.

## 화면별 동작

### 대시보드

- 선택한 일간·주간 기간에 존재하지 않았던 대분류는 행 자체를 숨긴다.
- 숨긴 대분류는 예산, 실제 기록, 분야 수, 목표 준수 점수에 포함하지 않는다.

### 통계

- 일간·주간·월간·연간 모두 동일한 활성 날짜 규칙을 사용한다.
- 기간 중 일부 날짜에만 활성이라면 그 날짜의 예산과 기록만 합산한다.
- 생성 전 기간에는 `0시간` 행으로 보여주지 않고 완전히 숨긴다.
- 온라인 통계와 오프라인 구조 통계가 동일한 결과를 반환해야 한다.

### 시간 예산

- 현재 날짜에 활성인 대분류만 편집한다.
- 생성 주에는 기존 주간 예산을 남은 날짜로 재분배하지 않는다.
- 저장된 주간 예산 문서에 대분류 값이 있더라도 날짜별 집계 시 생성 전 날짜의 예산은 0으로 처리한다.

### 시간 기록

- 수동 입력 날짜에 따라 대분류 선택지를 필터링한다.
- 타이머는 현재 활성 대분류만 표시한다.

### 기록 내역

- 정상적으로 생성된 기록은 그대로 표시한다.
- `createdDate`가 있는 대분류의 생성일 이전 비정상 기록은 숨긴다.
- 기존 대분류 기록은 모두 유지한다.

### 대분류 관리

- 생성일은 내부 적용 기준이며 수정 입력으로 제공하지 않는다.
- 기존 대분류에도 “생성일 미설정” 같은 불필요한 문구를 노출하지 않는다.

---

## 오프라인과 동기화

- 오프라인 스냅샷의 대분류 객체에 `createdDate`가 그대로 저장된다.
- 네트워크가 없을 때도 캐시된 `createdDate`로 날짜별 활성 여부를 계산한다.
- 새 대분류 생성은 현재 Firebase 온라인 저장 흐름을 유지한다. 생성 성공 후 받은 대분류에 `createdDate`가 포함되어야 한다.
- 온라인·오프라인 렌더러가 같은 공통 활성 함수와 요약 결과를 사용한다.

---

## 오류 처리

- 새 대분류 생성 시 현지 날짜를 얻지 못하는 경우는 현실적으로 발생하지 않지만, 잘못된 값은 저장하지 않고 생성 요청을 중단한다.
- 기존 데이터의 잘못된 `createdDate`는 시작일 제한 없음으로 해석하여 과거 데이터가 사라지는 것을 방지한다.
- 수동 입력 저장 차단 메시지는 날짜와 대분류 선택을 수정할 수 있도록 모달이 아니라 기존 경고 방식으로 표시한다.

---

## 테스트 범위

### 순수 도메인

- `createdDate` 없는 기존 대분류는 과거·오늘·미래 모두 활성
- 유효한 생성일의 전날은 비활성, 당일과 이후는 활성
- 잘못된 생성일은 기존 대분류처럼 활성
- 기간 종료일보다 생성일이 늦으면 기간에서 제외

### 일간

- 추가일 전날에는 행·예산·점수에서 제외
- 추가일부터 행과 계산에 포함
- 추가일 전의 비정상 기록은 집계하지 않음

### 주간

- 목요일 생성, 동일 요일 비율, 주간 7시간이면 4시간만 반영
- 생성 전 요일의 직접 일간 예산도 집계에서 제외
- 목표 준수 분모가 활성 날짜의 예산만 사용

### 월간·연간

- 생성 전 월에는 행이 없음
- 생성 월에는 생성일부터 말일까지 반영
- 연간 합계는 생성일 이후만 반영
- 여러 월 요약을 합칠 때 비활성 기간의 0시간 항목이 다시 생성되지 않음

### 입력

- 수동 입력 날짜 변경 시 비활성 대분류가 선택지에서 사라짐
- 추가일 이전 저장 요청 차단
- 오늘 생성한 대분류의 오늘 기록 허용
- 타이머 시작 시 현재 활성 여부 검증

### 데이터 보존

- 대분류 수정·일괄 저장이 `createdDate`를 덮어쓰지 않음
- 보관·복원 후 원래 생성일 유지
- `createdDate` 없는 기존 대분류의 과거 통계가 그대로 유지

### 회귀

- 성장·절제 달성률 계산 유지
- 카운트다운·카운트업·일시정지·복구 유지
- 기록이 있는 기간만 이동하는 탐색 유지
- 온라인·오프라인 통계 결과 일치
- PWA 새 모듈이 앱 셸에 포함되고 캐시 버전 갱신

---

## 구현 경계

이번 작업에는 다음을 포함하지 않는다.

- 기존 대분류의 실제 생성일 추정 또는 일괄 입력
- 사용자가 생성일을 수정하는 기능
- 미래 날짜부터 시작하도록 예약하는 기능
- 주간 예산을 남은 날짜에 자동 재분배하는 기능
- 대분류의 종료일 또는 임의 활성 기간 편집 기능

이 범위를 지켜 기존 통계의 의미를 보존하면서, 업데이트 이후 추가하는 대분류에만 정확한 시작일을 적용한다.
